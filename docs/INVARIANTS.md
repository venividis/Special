# Invariants

Statements that must hold in every reachable state. Each names the test
that tries to break it. If any of these can be made false, that is a bug
regardless of what else passes.

The form is IPSEITY's, which borrowed it from the Dave Held core: an
invariant written down is a claim that can be attacked, where a feature
list is only a claim that something happened. The numbering is DESIGN.md
§14's (A1 … H3), so a security-checklist row and its invariant are the
same line; `tools/invariants-check.mjs` (U12) asserts that every row below
names an assertion string that exists in the named file — a `test_…` as a
function in its `.t.sol`, an italic sentence verbatim in its `.mjs` (a
sentence a tool builds as a template literal counts, with only the holes
differing), a `--group g` citation in `tools/verify-site/g.mjs` — and that
this ledger and DESIGN §14 name the same rows with the same files and
sentences.

Discipline: a row is **live** only once its test runs in `npm run check`
and has been seen to fail under a one-character mutation. Until then it is
**pending** and names the unit that owns it. Counts and gas numbers are
written here only after a run.

The wave-1 integration flipped the unit rows below on two things: the
units' own mutation evidence, recorded in their commit bodies, and the
integrated runs (237 tests on each build; verify-vault 168, verify-parley
81, verify-launch 123, verify-steward 91, verify-timelock 35 against the
real hub; verify-pool 144 on its stand-in). The `test/Bundle.t.sol`
citations it added beside them are further evidence, not yet mutation-
gated — that gate, with E1/E3's, is U12's.

The wave-3 battery (U12) added two more provers beside the suites and the
standalone verifiers, each cited below by the sentence it prints:
`tools/verify-findings.mjs` replays every historical finding against the
compiled contracts deployed as every verifier deploys them — the attack is
performed and the refusal asserted, *refuted on HEAD*, and where a one-line
removal of the guard re-opens the hole the same attack is shown to succeed
against that variant, compiled separately, *reproduced* (36 verdicts, 31
refuted and 5 reproduced, 2 `n/a`, 0 failed on this tree); `tools/agents.mjs`
runs seven motives for 220 ticks over the real hub, three owned markets, a
graduated sealed market, a raise, the commons, a priced inbox and a session
key on a Reach that is sold and bought back under it, asserting the
invariants after every tick (seed 20261012: 6,723 checks held, 0 failed,
127.6 s on four cores shared with two mutation gates; seed 788110557, the
one a battery run drew: 6,727 held, 0 failed). `npm run check` is
`tools/check.mjs`: every step must print
exactly one summary line reporting zero failures, a missing step fails the
run, and incomplete is never pass. The E1/E3 mutation gate,
`tools/mutations.mjs`, is not in `check` because every mutation is a cold
viaIR compile; on this tree it read 19 mutations: 17 killed in a tree pruned to the two
contracts and their suites, P13 killed in the full tree by `test/Bundle.t.sol`
(`test_aBuyBackRevivesNothingAnywhere`, `test_panicRevokesAcrossEverySatellite`),
and one survivor, P11, named in E1 with the test it asks for.
