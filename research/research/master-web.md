## 1. Executive answers

### 1.1 How is the web UI delivered?

Two ways, and they are the same bytes.

1. **From chain, via tokenURI.** `ConfluenceRenderer.render()` returns `data:application/json;base64,…` whose `animation_url` is a `data:text/html` document: the "ANIMA GENESIS — Unfold your artifact" loader (`contracts/src/confluence/ConfluenceLoader.sol`, generated by `scripts/build-chain-loader.mjs` from `web/confluence/chain-loader.mjs` + `web/confluence/module-loader.mjs`, esbuild-minified, identifiers not mangled). The loader carries `window.AWE_CHAIN_IDENTITY = {seed, genome, root, chainId, collection, tokenId, manifest, privacyResource, runtime, sha256, archiveVersion}` and one `<input id="rpc" type="url">` + `<button id="unfold">`. On click it reads every chunk of the archive with raw `eth_call` (no library; selectors hard-coded) at one pinned block through either a user-supplied HTTPS/localhost RPC (stored on `window.AWE_CHAIN_RPC`) or `window.ethereum`, verifies SHA-256 in pure JS ("SHA-256 works in opaque data URLs, where SubtleCrypto may be unavailable", chain-loader.mjs:1-3), gunzips with `DecompressionStream`, builds an import map `awe/<path>` → `data:text/javascript;base64,…` for schema-3 feature modules, and then `document.open(); document.write(html); document.close();` (chain-loader.mjs:58-61). The loader is read-only: it never calls `eth_requestAccounts`. Docs justify the indirection: "Embedding the full application twice in tokenURI exceeded practical RPC execution limits; the compact loader avoids that large metadata allocation" and "Marketplace viewers without wallet injection require a CORS-enabled read-only RPC and must permit data-HTML execution" (docs/confluence/ARCHITECTURE.md, "Onchain application archive").
   - Archive schemas the loader understands (chain-loader.mjs:20-45): v1/v2 `OnchainApp`/`OnchainAppDirectory` (selectors `chunkCount 0xf91f0937`, `schemaVersion 0x4e2ce6d3`, `byteLength 0x02823108`, `readChunk 0x8f5281bf`; chunk limits 64 / 512; chunk 1..23,000 bytes STOP-prefixed) and v3 `OnchainModuleDirectory` (`"anima.functional-runtime/1"`; module-loader.mjs selectors `0x334f7ac5 count`, `0x7259f506 shellIndex`, `0xd216d296 moduleAt(i)` 8 words, `0xb3a840da depCount`, `0xb972ae05 dependency`). v3 entries 2..32, ≤64 MiB, each module an `anima.module-envelope/1` gzip wrapping `anima.functional-module/1`; "Shell must pin every feature" (module-loader.mjs:38).
   - Measured (docs/MASTER-BUILD.md, reports/master-7.0/summary.json): Genesis app 7,952,983 bytes recovered in 6,080 ms; 101 chunks / 117 modules / 20 feature groups; the Module Workbench is a second on-chain HTML archive of 707,014 bytes / 31 chunks / sha256 `ec2a47d8697ecbce4560dbe5f07dede41b1616f223ea81196bb947dbe79dc2b6`; the 15,112,663-byte RAILGUN worker is a `ShardedResource` recovered on demand (web/privacy/recover-resource.mjs, concurrency 4 default / 8 max, ≤8 shards default / 64 max).
2. **As a static build for development.** `scripts/build-confluence.mjs` → `scripts/lib/runtime-build.mjs: composeRuntime(root)` parses `web/index.html`, strips `assets.js`/`app.js`/`styles.css`, appends 17 stylesheet links, injects `<script id="optical-assets">` (`ASSETS = {shader, original, wasm, referenceHTML}`), `<script id="original-runtime">` (esbuild IIFE of `web/app.js`), `web/instruments/shell.html`, `<script id="instrument-runtime">` (esbuild of the rehearsal controllers), `web/confluence/shell.html` and `<script type="module" src="web/confluence/app.js">`; writes `dist/{index.html, modules.html, original.html, abis/CartridgeRegistry.json, manifest.webmanifest, build-manifest.json ("anima.source-build/1")}` and the root `index.html` (477,361 bytes). `npm start` serves it at `127.0.0.1:4173`. `preview.html` (455,670 bytes, title "i dont fucking believe it!") is a historical build; `test/browser/README` states the acceptance harness "never reads or serves historical preview.html". The approved reference HTML is pinned: `APPROVED_SHA256(web/reference/approved-1.2.html) = 6b1fb23f63cf5aa65283b8be2f1446dddae38622b7ea8c164249c8cc74146bb6`.

Neither `index.html`, `web/index.html` nor `web/confluence/shell.html` carries a Content-Security-Policy meta (grep count 0 in each); only `<meta name="referrer" content="no-referrer">`. CSPs exist only on the sandboxed iframes the app spawns (cartridges, modules, calendar preview).

### 1.2 How does the app verify NFT ownership for access?

Ownership is checked inside the app, repeatedly, never once at the door. Four verifiers exist:

- **`ConfluenceWallet.connect(collection, tokenId)`** (web/confluence/wallet.mjs:47-156): `assertMintBinding(window.ANIMA_SIM_SAMPLE ? null : window.AWE_CHAIN_IDENTITY, …)` refuses any collection/token/chain other than the one baked into the token's own loader ("Connect the collection and token belonging to this minted Anima." / "Switch your wallet to this NFT's home chain X.", minted-identity.mjs); `eth_requestAccounts`; at one pinned block reads `ownerOf(tokenId)`, `accountOf(tokenId)`, `renderSnapshot(tokenId)` (17 words) and `modulesOf(address) returns (address[6])` from the manifest; `if (owner.toLowerCase() !== address.toLowerCase()) throw Error("This wallet does not own the selected NFT.")`; the ERC-6551-style account must have code; each of the six modules `["market","vault","journal","ledger","cartridges","exit"]` must have code. The owner is then re-asserted by `assertOwner()` (wallet.mjs:259-278: ownerOf, `currentOwner()`, `mode()==0` else "proof-authorized execution" error) and `assertReviewContext(revision, epoch)` (wallet.mjs:397) before every signed action and after every read-then-sign gap; `send()` (wallet.mjs:515) refuses plans older than 300,000 ms.
- **`NFTAccountSession.connect(provider, signer, identity)`** (web/launchpad/account-session.mjs): `ownerOf == signer`, runtime bytecode of the collection pinned to `IDontFuckingBelieveIt` and of the account to `SovereignAccount` with immutable masks ("Pin the whole executable and require every occurrence of each immutable to agree."), `currentOwner == owner`, `mode == 0`, `sessionEpoch` captured; `wrap(plan)` turns an EOA plan into `executeUtility(nonce, deadline, asset, target, value, data, allowance)` — "No delegate is installed: each call is signed by the current NFT owner."
- **`RegistryAdapter.context()`** (web/modules/adapter.mjs): `assertOwner()`, then `sdk.readRegistry` and `read.owner == w.address && read.currentOwner == read.owner`.
- **`CartridgeRegistry.launchManifest(id, player)`** (integrations/console/protocol/runtime-contracts/src/CartridgeRegistry.sol:119-136): computes `controller = parentId == 0 ? holder : artifact.ownerOf(parentId)` and `authorized = player != 0 && player == controller`; `ConfluenceWallet.readCartridge` (wallet.mjs:216-258) additionally requires `holder == account`, `controller == address`, `onchainContentAvailable`, and `sha256(contentOf(id)) == contentHash` before executing.

**The gap that matters for the GOAL:** only the Live desk (NativeMarket/TimeVault/MemoryLedger/WorldLedger via `prepareUtility`/`preparePersonal`), the Module Workbench, cartridges, the Workshop and the Launchpad's "Use this NFT account" funding mode are NFT-gated. The **Swap destination (`web/v4/desk.mjs`) has no NFT check at all** — it signs with a RAILGUN shielded wallet (default, "Public signing is never used as a fallback.") or an injected public wallet. **Commons/MLS, Governance, Crosschain, Lifecycle and the Launchpad's default "Use wallet funds" mode sign with `LaunchChain`'s EOA wallet**, and `CommonsDesk` says so by design: "Encryption keys belong to your wallet; selling an NFT does not transfer your private history." The Participant page (`web/launchpad/participant.mjs`) is explicitly for people with no NFT. So "mint → everything gated by the NFT" is only partially true in this repo.

## 3. Build pipeline

`scripts/build-confluence.mjs` + `scripts/lib/runtime-build.mjs` compose one HTML from `web/index.html` as described in §1.1. The instrument runtime preamble imports `kingdom/model`, `instruments/engine`, `operating/engine`, `memory/crypto` + `engine`, `exit/engine`, `LIVED_ASSETS` and `IX_CATALOG` (from `web/instruments/capabilities.json`). `RESOURCES = [web/cartridges/lumen-drift.html, web/privacy/railgun-worker.js]` are archived as `ShardedResource`s. `scripts/build-chain-loader.mjs` concatenates `chain-loader.mjs` + `module-loader.mjs` with import/export lines stripped and emits the Solidity `ConfluenceLoader` library — so the loader JS and the contract are one source; `verify-confluence` round-trips tokenURI byte-for-byte. The runtime-graph build (`modules:build`) discovers imports from the shell and partitions them into the 20 feature groups with per-group versions; test "a real minted NFT embeds the immutable schema3 loader and its exact onchain feature edition" (test/browser/current-app.mjs) pins that.

Reuse: **adapt**. The STOP-prefixed chunk + directory + gzip + import-map scheme is the strongest "mint a website" mechanism among the four repos for a multi-megabyte app, but it depends on a browser being allowed to run `data:` HTML and on a CORS RPC; the merge should keep the loader but serve it also under `web3://` (IPSEITY's Premises) so marketplaces without data-HTML execution still render.

## 17. Weaknesses and TODOs
1. Swap/Commons/Governance/Crosschain are signed by an EOA or RAILGUN wallet, not the NFT account (§1.2) — the GOAL's "all features through the NFT" is only true for Live/Workbench/cartridges/NFT-funded launches.
2. `V4Desk` default-on privacy with no public fallback makes the swap unusable without RAILGUN infrastructure; and shielded launches obscure the creator ("Never infer a creator wallet from that adapter").
3. No page-level CSP on the shell; `launchHTML` and the workshop preview allow `'unsafe-inline'` scripts inside sandboxes (acceptable only because `connect-src 'none'` and opaque origin).
4. `GenesisV4Launchpad` uses `require` strings (`TERMS/BUSY/PAIR`) against the custom-error convention of the other repos; `OwnerV4FeeHook` has a mutable `owner` (two-step) — a hook owner can raise fees up to `committedMaximumFee` after launch unless `commitPolicy(exactFee)` was called.
5. `ArtifactAccount` deploys with `new` (no CREATE2) and is "not an ERC-6551 implementation"; `AWEArtifact.mint` is permissionless and unbounded.
6. `CartridgeRegistry.MAX_CONTENT_BYTES 24576` (single slot store) forces the chunked successor for anything real; `_validate` does not validate JSON.
7. Many desks depend on loopback services (rehearsal/proof/scenario/world) that are not part of a chain deployment; docs call the Groth16 setup `single-machine-development-only`.
8. The `renderSnapshot` 17-word tuple and `modulesOf(address[6])` are hard-coded in the wallet; adding a module changes the ABI the loader expects.
9. ethers is bundled three times (vendor/ethers.min.js, modules/embedded.mjs, railgun worker); the on-chain archive stores all of them.
10. Mainnet is "blocked" in `web/evm.mjs` and `experimental.mjs` but allowed in `V4_NETWORKS` (1/42161/137) — inconsistent chain policy.
11. Docs numbers drift (755 vs 760 tests; MASTER-BUILD vs summary.json).
12. No `web3://` route at all — tokenURI data-HTML only; marketplaces that strip `animation_url` scripts show nothing.
13. Custom P-256 envelope protocol is self-declared "neither HPKE nor MLS" and not forward secure; two parallel E2EE stacks.

## 19. Pitfalls for the merge team
- The loader runs inside an opaque `data:` origin: no `SubtleCrypto` guarantee (hence pure-JS SHA-256), no `localStorage` persistence across marketplaces, and `document.write` replaces the Window — anything the shell needs must be on `window.AWE_CHAIN_IDENTITY` before the write.
- `ANIMA_SIM_SAMPLE` disables mint binding; never ship a build with it set.
- Immutable masking (`normalizeRuntime`) is how every contract address is accepted; if the unified contracts change constructor immutables, regenerate every `artifacts.mjs` (v4, launchpad hook-artifacts, extensions, commons, workshop, governance, crosschain) or every desk refuses to connect.
- `executeUtility`'s single-asset allowance means a plan may approve at most one ERC-20; multi-token actions must be split.
- `prepare*` plans are tied to `revision` and `sessionEpoch`; any read-then-sign gap must call `assertReviewContext`.
- `finishRecord` demands exactly one `Launched` event and the `finalized` tag — on chains without finality tags (ganache) the tests use a fallback.
- Keep the three chunk-reader selector tables (`chain-loader.mjs`, `module-loader.mjs`, `recover-resource.mjs`) in lockstep with the Solidity; they are hand-coded 4-byte constants.
- The `modulesOf` manifest is read from `AWE_CHAIN_IDENTITY.manifest` — a module registry that is not the collection itself; the unified token should expose the module addresses on the token contract.
