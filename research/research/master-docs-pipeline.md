## 0. Executive summary (what this repo is, in the terms of the GOAL)

ANIMA MASTER is the "everything" branch of the ANIMA lineage: a Solidity/EVM ERC-721 (`IDontFuckingBelieveIt`, 20,940 deployed bytes) whose every token gets a deterministic CREATE2 account (`SovereignAccount`, 21,506 bytes, custom — explicitly *not* canonical ERC-6551), a renderer (`ConfluenceRenderer`) whose `tokenURI` emits a self-contained `data:text/html` boot page that recovers an entire multi-megabyte web application from immutable `AppChunk` contracts, and, since v7, an owner-installable module system (`TokenModuleRegistry`/`ExtensionReleaseRegistry`/`ModuleStateStore`/`ModuleWorkbench`) plus a chunked legacy cartridge registry. It bundles a Uniswap v4 launchpad, an internal AMM (`NativeMarket`), a community sale (`GenesisLaunchpad`), a streaming auction, time-locked vaults (`TimeVault`, `VestedExitVault`), onchain group chat (`EpochGroupChat`, `MLSGroupChat`), a LayerZero V2 witness portal, RAILGUN shielded execution, and ~50 more "modules" (see `system-manifest.json`, 56 module entries).

Relative to the GOAL ("one ERC-721 that mints a website with swap, messaging, launchpad, vault; no server, no IPFS"):

- **Website from chain: yes, but via `tokenURI`'s `animation_url`, not via `web3://`.** The boot page is a ~15 KB loader stored in an `AppChunk` created in the renderer constructor (`contracts/src/confluence/ConfluenceRenderer.sol:43-45`), which pulls 101 chunks / 20 feature archives through `eth_call` at one pinned block, SHA-256-verifies them with a hand-rolled SHA-256 (because SubtleCrypto is unavailable in opaque `data:` origins — `web/confluence/chain-loader.mjs:2`), and `document.write`s the 7,952,983-byte application. The project's own standards review states there is "no manual resolver, raw-path fallback, index route, asset routing, or web3 client integration" (`docs/confluence/research/standards.md:33`). The hosted copy (`dist/index.html`, served by `scripts/serve-confluence.mjs` on 127.0.0.1:4173) is a convenience, not the delivery mechanism.
- **Wallet gating: client-side owner check + contract-side authority.** `ConfluenceWallet.connect` requires the wallet's selected account to equal `ownerOf(tokenId)` at one block ("This wallet does not own the selected NFT.", `web/confluence/wallet.mjs:89`) and binds the selection to the token's own embedded `AWE_CHAIN_IDENTITY` (`web/confluence/minted-identity.mjs:26-40`). The workbench's `RegistryAdapter.context` additionally requires `SovereignAccount.currentOwner()` to equal `ownerOf` and the `sessionEpoch` to be unchanged across every reviewed transaction (`web/modules/adapter.mjs:11-22`). Writes are enforced by the contracts (Bound-mode `execute` resolves `ownerOf` at call time; `TokenModuleRegistry` requires the canonical account, expected catalog root and custody epoch — `docs/MODULES-IMPLEMENTATION.md:20`). Reads are open.
- **Deployed where:** on `main`, *only* disposable local chain 31337 (Ganache, Shanghai). A side branch (`origin/codex/deploy-on-testnet-and-mint-3-nfts-pj8cqs`, commit `33f1034`, 2026-09-19) records a **live Ethereum Sepolia deployment** with three minted tokens and the full module system (collection `0xCB8Dc18d3Ca5C9c2aeA16c94fa0af6EF4dfc0aC6`); that record is not on `main`, and `packaging.json:11` still says `"publicChainDeployed": false`.
- **Verification claimed:** GitHub Actions run 35172184548 on commit `84961c3`: 24/24 local stages, 760/760 root JS tests, 11 official-launch, 1 MLS, 9 Rust, 51 module tests, 7 native Forge tests + 64 fuzz runs, 17 Chromium scenarios (Chromium 151.0.7922.34). ### 2.4 `scripts/archive-confluence.mjs` (71 lines) and `scripts/verify-confluence.mjs` (92 lines)

Default (schema 3, `awe.onchain-runtime/3`): `writeRuntimeModules` splits the expanded runtime into **20 independently gzip-compressed feature archives** (`onchain-app/confluence/manifest.json`: `core-shell@4` 241,043 stored bytes, `launchpad@1` 561,363, `modules@8` 381,399, `extensions@4` 289,227, `vendor@1` 211,487, `commons@1` 111,543, … ; total `byteLength` 2,072,940, `expandedBytes` 7,952,983, `sha256` `479d97b6…2e13`, `runtimeHtmlSha256` `7ca876f3…5fb0`). `--legacy` keeps the v1/v2 single-archive producer: gzip level 9 inside a boot HTML that decompresses with `DecompressionStream("gzip")` and `document.write`s (lines 15-21), 23,000-byte chunks, shards of 32 chunks when >64 chunks, 512-chunk cap.

`verify-confluence.mjs` rejects an archive whose `buildManifestSha256` or module graph differs from the current build, re-reads the chunks, compares the expanded runtime byte-for-byte with the current build, checks exactly one `importmap`, that every import is `data:text/javascript;base64,` (no external module), that every embedded module's references resolve inside the map, and syntax-checks every script with `node --check` (lines 25-80).

`docs/FUNCTIONAL-ONCHAIN-MODULES.md:19-21` describes recovery: "Schema 3 first recovers the entire module directory at one block, verifies its content commitment and dependency versions, and then reads each feature archive at the same block … Recovery is currently eager: every feature is verified before application execution … this is not a claim of lazy first-use loading."

The loader HTML (`scripts/build-chain-loader.mjs:4`) shows "ANIMA GENESIS … Recover its full particle world through a wallet or a read-only RPC", an optional HTTPS RPC field, and an "Unfold my artifact" button.

4. **Companion surfaces**: the module workbench is a separate 707,014-byte document anchored by `ModuleWorkbench` (`services()` returns chainId, collection, installations, releases, stateStore, document, documentHash — `contracts/src/modules/ModuleWorkbench.sol:59-68`); it is recovered by CLI and "Serve that recovered directory on a trusted local origin to use a browser wallet" (`docs/MODULES-DEPLOYMENT.md:75`). It is *also* embedded in the Genesis app (`modules@8` feature archive, `dist/modules.html`).
5. **Not provided**: no `web3://` (ERC-4804/6860) resolver, no `resolveMode`, no ENS content hash, no path routing; the hosted `dist/` is served by a local static server or (sibling repo) GitHub Pages. The privacy worker, RAILGUN circuits, RPCs, Waku, keepers and world servers are external.

### 6.2 How ownership is verified for access

- **Reading is open.** Anyone with an RPC can unfold the artifact (`chain-loader.mjs:54-56`), read participant launch pages ("Public terms can be read through an explicitly selected HTTPS RPC before wallet connection", `LAUNCHPAD.md:49`), and recover modules/state.
- **Original app, "Connect NFT"** (`web/confluence/wallet.mjs:47-100`): `assertMintBinding(window.AWE_CHAIN_IDENTITY, collection, tokenId[, chainId])` refuses any other collection/token ("Connect the collection and token belonging to this minted Anima.") or chain ("Switch your wallet to this NFT's home chain …", `minted-identity.mjs:26-40`); `eth_requestAccounts`; at one block, `ownerOf`, `accountOf`, `renderSnapshot`; **`owner !== signer` → "This wallet does not own the selected NFT."** (line 88-89); account must have code. `refresh()` re-reads `ownerOf`/`accountOf`/`eth_chainId`/`eth_accounts` at one block and invalidates on any mismatch ("NFT custody or wallet context changed. Connect again.", lines 160-184). `accountsChanged`/`chainChanged` invalidate. Every prepared review captures `sessionEpoch` and re-checks it before signing (lines 283-411).
- **Workbench** (`web/modules/adapter.mjs:11-22`, `app.mjs:107`): `wallet.connect(collection, tokenId)` then `readRegistry` must return `collection == wallet.collection`, `account == wallet.account`, `owner == wallet.address`, and `currentOwner == owner` (`SovereignAccount.currentOwner()`), else "Registry identity or current NFT custody does not match."; `fresh(expected)` re-asserts `sameAuthority` (chainId/registry/collection/tokenId/account/owner/epoch) immediately before each send, and that the release is still the enabled module. UI copy: "Connecting checks the current owner, account and custody epoch. It does not install or send anything." (`app.mjs:16`).
- **Contracts enforce writes.** Bound-mode `SovereignAccount.execute` resolves `ownerOf(tokenId)` at call time, so authority follows transfer automatically (`docs/ARCHITECTURE.md:58-61`); `TokenModuleRegistry.activate/writeState/stageState/disable` require `msg.sender == accountOf(tokenId)`, the expected catalog root, and the account's current `sessionEpoch` (`MODULES-IMPLEMENTATION.md:20`; `modules-stack.mjs:86-91`); custody-changing callbacks "invalidate and roll back delegated execution" (`SECURITY.md:7`).
- **"Authorised by the holder"**: at contract level Bound authority includes holder, token approval, operator approval, and narrow session keys (exact target, selector, value cap, window, call count, epoch — `docs/ARCHITECTURE.md:63-69`; 6.1+ "exact-calldata instrument grants with a selected-asset net-debit budget" — `SECURITY.md:7`), plus `SessionSponsor` relayed vouchers and `AgentPolicyGuard`. The *UI recipes*, however, require the exact owner in Bound mode: "Proof-authorized account mode requires its separate authorization flow and is intentionally rejected by this adapter." (`packages/modules/README.md:117`). The browser fixtures use an injected EIP-1193 provider with deterministic addresses; "it does not prove … real ownership" (`test/browser/README.md:35`).

## 8. Unique ideas worth carrying forward

1. Loader-in-an-`AppChunk` created by the renderer constructor and copied with `extcodecopy` so the recovery program costs no EIP-170 runtime bytes (`ConfluenceRenderer.sol:43-45`).
2. Hand-rolled SHA-256 in the loader because SubtleCrypto is unavailable in opaque `data:` origins (`chain-loader.mjs:2`).
3. Schema-3 "functional feature archives": 20 independently versioned, independently gzip-compressed archives under an `OnchainModuleDirectory` whose content commitment excludes addresses so unchanged features can be reused across editions (`FUNCTIONAL-ONCHAIN-MODULES.md:13-15`).
4. Pinned-block, single-snapshot recovery everywhere (browser, SDK, CLIs) with block-hash re-check before returning.
5. Per-NFT module registry with append-only catalog roots, custody-epoch binding, and explicit staged migrations; state bytes stored as `AppChunk` code (not SSTORE) to fit EIP-7825's 16,777,216 tx gas cap — measured 7.87 M gas for 32 KiB.
6. The validation runner's candidate-input fingerprinting and "incomplete ≠ pass" test-summary parsing.
7. Deployment plans with predicted CREATE addresses, exclusive output files, journaled receipts, `ArchiveCreated` postcondition verification (defence against the shared-factory nonce race), and literal `--confirm` tokens.
8. Owner-reviewed "ReviewedAction" pattern: prepare → simulate → show exact calldata/gas → recheck owner/epoch/root → send once; stale previews invalidated by revision counters.
9. The cartridge NFT acquired *by the NFT's account* (`master-local.mjs:70-71`): nested ownership without ERC-7401.

## 9. Weaknesses, gaps and TODOs (from the docs' own admissions plus observation)

- No `web3://` surface at all; the "website" is a `data:` URI that must be opened by a wallet or marketplace that renders `animation_url`, and the app is ~8 MB expanded / 2 MB stored — recovery is eager (every feature before boot). `tokenURI` itself needs a 90,000,000 gas `eth_call` in the fixtures (`genesis-stack.mjs:55,64`) because the renderer base64-encodes the loader; public RPC limits may reject it.
- Public deployment is off `main`; the Sepolia record lives on an unmerged branch; `packaging.json` and `system-manifest.json` still say not deployed. The three Sepolia mints are not itemised.
- Custom account, not canonical ERC-6551; no ERC-7401; ERC-8004 binding unverified (`standards.md`). `supportsInterface` does not advertise an execution interface.
- Massive surface: 204 artifacts, 56 "modules", RAILGUN (15 MB worker, 51 dependency advisories), LayerZero, Groth16 with dev trusted setup, Rust kernel, Python render parity — much of it marked `LOCAL_SERVICE_AND_CONTRACTS` or `RESEARCH_NOT_IMPLEMENTED` in `system-manifest.json`.
- Shared `ModuleArchiveFactory` CREATE-nonce race between planning and signing is detected, not prevented (`MODULES-IMPLEMENTATION.md:56`).
- Direct module state capped at 32 KiB; larger state must be a separately deployed archive; all unencrypted bytes public; no key handover on transfer.
- Workbench HTML modules run in a worker with a tiny DOM subset — arbitrary legacy HTML may not run.
- Toolchain fragility: viaIR builds "can take hours" (CI comment), Ganache needs `/dev/shm` `TMPDIR` on some executors (`PRODUCTION-VALIDATION.md:44-54`), Forge must be the native binary, DOM tests need `linkedom` from a nested package.
- Historical numbers drift across docs (`reports/README.md` warns); `CHANGELOG.md` stops at 5.9.
- Mainnet is rejected by every planner; the supported-wallet list for the v4 desk (1, 42161, 137) is a UI setting, not a deployment.
- Admin keys exist until frozen: collection admin (factory once, royalties), `ProofRouter`, `ThresholdAttestationVerifier`, `OmnichainWitnessRegistry` (`docs/SECURITY.md:34-66`); the Sepolia deployer is "the initial administrator for the core, proof router and verifier" (`GENESIS-DEPLOYMENT.md:41`).

## 11. Pitfalls for the design team

- Do not read `reports/release-status.json`, `protocol-status.json` or `reports/VALIDATION.md` as current: they describe the 1.2 candidate whose Solidity was never compiled (`reports/README.md:9-12`).
- `docs/SECURITY.md`, `ARCHITECTURE.md`, `PROTOCOL.md`, `DEPLOYMENT.md` are flagged "Historical research architecture"; the current boundaries are in root `SECURITY.md` and `docs/CAPABILITIES.md`.
- `contracts/src/confluence/ConfluenceLoader.sol` and ~22 `web/*/artifacts.mjs` files are **generated** (`local-validation.mjs:64-88`); editing them by hand is undone by the next compile/build.
- The core fixtures compile for **Shanghai** (`compile:local`) while `npm run compile` targets Cancun and v4 is Cancun-only; a plan must use one profile throughout (`GENESIS-DEPLOYMENT.md:19`).
- `tokenURI` reads in tests pass `gasLimit: 90_000_000`; assume public RPCs cap `eth_call` gas far lower.
- `master:local` refuses to reuse an instance after the workbench source changes; use `MASTER_INSTANCE`.
- The Sepolia runner stops on any nonce or predicted-address mismatch; never "fix" a journal by hand (`MODULES-IMPLEMENTATION.md:56`: "Never edit a saved journal's success labels to manufacture completion.").
- The `integrations/github/*/deployments/*.json` files are the *other* repos' records, not MASTER's.
- The MASTER's own standards review says the project must not be presented as live `web3://` hosting or ERC-6551-compatible.
