## 1. `contracts/comms/AgentComms.sol` — priced, authenticated agent messaging (7,368 B runtime)

### Purpose
"A market for agent attention" (L23). Three things only: **authenticated sender identity** (the contract checks `isController(fromAgentId, msg.sender)`), **priced attention with a refund** (postage is escrowed and collectable *only by replying*; if the window lapses the sender takes it back), and **commitment, not content** (only `keccak256(ciphertext)` plus a transport URI go on-chain). The header is explicit about what it refuses to do:

> "Most 'on-chain chat' is a string in an event, which is a worse version of a database and gets used by nobody. The parts of messaging that genuinely need a blockchain are narrow, and this contract implements only those" (L28-30) … "On-chain bytes are the most expensive storage ever built and the least private; putting conversations there is a category error." (L43-44) … "What this deliberately does not do is ordering or delivery guarantees. Those are the transport's job, and a contract that pretended to provide them would be lying." (L46-47)

`IAnimaCommsView` (L12-16) needs only `isController`, `accountOf`, `keyRegistry` from the token; `IEncryptionKeyView.keyIdOf` (L18-20) from the key registry.

### Storage layout
- `Inbox {address feeToken; uint128 postage; uint64 replyWindow; bool open; bool configured;}` (L57-63) — `feeToken == 0` means "accepts no paid mail"; `open == false` means allowlist-only.
- `Message {uint256 fromAgentId; address sender; uint256 toAgentId; uint128 postage; address feeToken; uint64 sentAt; uint64 replyBy; bool answered; bool refunded; bytes32 payloadHash; bytes32 threadId;}` (L65-77) — `fromAgentId == 0` means a plain account wrote.
- `uint256 private _nextMessageId = 1;` (L93) and `mapping(uint256 => Message) private _messages;` (L94). **There is no public getter for `_nextMessageId` and no per-agent or per-thread index** (confirmed from the ABI: only `messageOf(uint256)`). An on-chain-only client cannot enumerate an inbox without `eth_getLogs` over `MessageSent`.
- `recipientKeyOf` / `replyKeyOf` (L97-98): zero means "legacy commitment-only path; encryption not enforced" (comment L95-96) — kept as separate mappings so the original `Message` ABI did not change.

### Events (L104-128)
`InboxConfigured(agentId, feeToken, postage, replyWindow, open)`, `SenderAllowed`, `AgentSenderAllowed`, `MessageSent(messageId idx, toAgentId idx, fromAgentId idx, sender, threadId, payloadHash, postage, replyBy, transportURI)`, `MessageAnswered(messageId idx, toAgentId idx, payloadHash, postage, transportURI)`, `PrivateEnvelopePinned(messageId, recipient, keyId)`, `PrivateReplyPinned`, `PostageRefunded(messageId, to, amount)`, `Broadcast(fromAgentId idx, topic idx, payloadHash, transportURI)`. The `transportURI` NatSpec: "an XMTP topic, a Waku content topic, an ipfs:// CID, or an https:// endpoint. Consumers MUST verify the fetched bytes hash to `payloadHash`" (L108-110).

### Custom errors (L134-148, 18 in ABI incl. inherited)
`NotAgentOwner`, `NotAgentController`, `InboxClosed`, `SenderNotAllowed`, `NoSuchMessage`, `AlreadyAnswered`, `AlreadyRefunded`, `ReplyWindowClosed(replyBy)`, `ReplyWindowOpen(replyBy)`, `BadReplyWindow`, `EmptyPayload`, `PostageAboveLimit(postage, maxPostage)`, `UnexpectedFeeToken(expected, actual)`, `NoEncryptionKey(recipient)`, `EncryptionKeyChanged(expected, actual)`; plus `InexactERC20Transfer`, `SafeERC20FailedOperation`, `ReentrancyGuardReentrantCall`.

### Access control
- `configureInbox`, `setSenderAllowed`, `setAgentSenderAllowed`: **token owner only** (`AGENTS.ownerOf(agentId) == msg.sender`, L170/178/186) — not controllers, so an ERC-4907 tenant or operator cannot reprice the inbox.
- `send`/`sendPrivate`: anyone, but if `fromAgentId != 0` the caller must be a controller of that agent (`ANIMA.isController`, L256-258). `isController` (AnimaAgent.sol L189-195) = owner, or unexpired ERC-4907 user, or an operator under the current `operatorEpoch` — so a sale revokes the right to write as the agent (tested).
- `reply`/`replyPrivate`: any controller of `toAgentId` (L332); postage is paid to `ANIMA.accountOf(toAgentId)` (L339), **the agent's ERC-6551 account, never the caller**: "an agent's correspondence funds the agent rather than its owner's wallet" (L302-303).
- `refund`: **permissionless** after `replyBy` (L345-346).
- `broadcast`: controller of `fromAgentId` (L371).

### Invariants and design decisions (with the load-bearing comments)
1. **Recipient cannot reprice pending mail.** `expectedFeeToken` + `maxPostage` are checked against live inbox config (L262-265): "Those last two are not ceremony. Postage is read from live inbox configuration the recipient controls, so without a caller-supplied bound a recipient could watch a pending `send`, raise its postage to the sender's entire allowance, reply immediately, and collect it." (L203-206). Regression: `Regressions.test.ts` L196-219 "refuses postage raised above what the sender agreed to", L221-233 "refuses a fee token the sender did not price against".
2. **Allowlist by agent id, not address**: "Agents rotate session keys; an address allowlist would have to be rewritten every time." (L183-184).
3. **Exactly one of {answered, refunded}**: `_reply` checks `answered`, `refunded`, `block.timestamp > replyBy` in that order (L329-331); `refund` requires `block.timestamp > replyBy` (L352). Tests: "refuses a late reply even when nobody has claimed the refund yet", "refuses a reply after a refund and a refund after a reply".
4. **Value-conserving escrow**: `transferFromExact` / `transferExact` (`libraries/ExactERC20.sol` L16-32) revert on fee-on-transfer mismatch.
5. **Key-pinned private envelopes**: `sendPrivate` resolves `AGENTS.ownerOf(toAgentId)`, reads `keyIdOf(owner)` from the registry the token names, requires non-zero and equal to `expectedRecipientKeyId` (L234-237): "a key rotation in the mempool makes the transaction fail instead of recording an undecryptable message" (L222-223). `replyPrivate` does the same for the original `m.sender` (L317-319). The SDK's `privateEnvelopeHash` (sdk L484-505) is the recommended `payloadHash`.
6. `EmptyPayload` rejects a zero commitment (L253, L333, L372).
7. CEI + `ReentrancyGuardTransient` (transient storage; needs Cancun).

### Gas / size
Runtime 7,368 B, initcode 7,608 B. Each `send` writes a 12-field `Message` (~5 slots) plus the `_nextMessageId` increment and an ERC-20 pull; no repo measurement of comms gas exists (`Gas.test.ts` benchmarks only the token).

### Tests
`test/Comms.test.ts` (12 `it`): "escrows postage on send and pays it to the agent's account on reply", "refunds the sender when the agent ignores the message", "enforces the allowlist on a closed inbox", "allowlists a peer by agent id, so rotating session keys does not break it", "refuses to let anyone write as an agent they do not control", "lets an operator write as the agent, and stops doing so once it is sold", "refuses a broadcast from a non-controller", "rejects an empty payload commitment", "pins the exact recipient key and rejects missing, stale, or rotated keys", "pins an encrypted reply to the original sender's key". Plus the two Regressions above. Live: `scripts/testnet-scenario.ts` act 7 (open inbox at 5 aUSD, client pays), `testnet-everything.ts` (send/reply/broadcast), `testnet-town.ts` (12 residents, closed inboxes, agent-id allowlists, circular paid conversation — 60 agents across 5 chains).

### Weaknesses / TODO relative to the goal
- **No enumeration** (private `_nextMessageId`, no inbox/thread arrays). For a website served from chain with no indexer this is fatal; the unmerged `AnimaCommons` shows the fix pattern (`_postIds[circleId]` + `postsPage`).
- Payload is off-chain by design; a "fully on-chain messaging" requirement needs an on-chain-body option (AnimaCommons stores ≤1,024-byte bodies; IPSEITY's Parley stores bodies in logs).
- ERC-20 postage only (native deliberately unsupported, see `docs/DEPLOYMENT.md` L107-112).
- `sendPrivate` pins the **owner's** key, not the operator's or the agent account's — an agent run by an operator must share the owner's decryption key.
- Zero-postage open inboxes are spammable; spam economics rely entirely on postage.
- Nothing stops the legacy `send` from recording an undecryptable payload (documented in `docs/PRIVACY.md` table row "Messages").

**Reuse verdict: ADAPT.** Keep the escrow/refund/identity model, the `maxPostage`/`expectedFeeToken` guard, agent-id allowlists and key pinning verbatim; add per-agent/per-thread id arrays with paged views, a `nextMessageId()` getter, an optional on-chain body (bounded bytes), and native-postage support if the unified protocol wants ETH.

## 2. `contracts/omni/` — LayerZero V2 home/mirror bridge

### 2.1 `ILayerZeroV2.sol` (64 lines)
Hand-transcribed `MessagingParams`, `MessagingReceipt`, `MessagingFee`, `Origin`, `ILayerZeroEndpointV2 {quote, send, setDelegate, eid}`, `ILayerZeroReceiver {allowInitializePath, nextNonce, lzReceive}`. Why local: "that package's `exports` map does not expose its `contracts/` subpath, so a Node-resolution build cannot import it. Transcribing … keeps the build hermetic and keeps the ABI byte-identical to the deployed endpoints." (L8-11). `docs/DEPENDENCY_SECURITY.md` records that removing the two unused LayerZero npm packages deleted 130 transitive packages. **Reuse verbatim.**

### 2.2 `AnimaOmniCodec.sol` (57 B library stub)
`struct AgentSnapshot {bytes32 to; uint256 agentId; bytes32 brainRoot; uint64 brainEpoch; bytes32 manifestHash; bytes32 weightsRoot; uint8 seal; uint64 homeChainId; bytes32 homeToken; string agentURI;}` (L12-23). `encode`/`decode` are plain `abi.encode`/`abi.decode`: "Hand-packed cross-chain codecs save a few hundred gas and have produced a remarkable number of critical bugs; the ABI coder is the audited option and its length-prefixing makes a truncated payload fail to decode rather than silently decode into something else." (L27-30). Rationale for carrying commitments: "The default ONFT721 message carries only `(to, tokenId)`, which is enough to move a collectible and not nearly enough to move an agent" (L6-7). **Reuse verbatim** (adapt the struct to the merged token's state).

### 2.3 `AnimaOApp.sol` — abstract OApp base (peer auth, rate limit)
API: `ENDPOINT` immutable; `mapping(uint32 eid => bytes32 peer) public peers` (L41); `struct RateLimit {uint64 windowSeconds; uint64 capacity; uint64 windowStart; uint64 used;}` + `mapping(uint32 srcEid => RateLimit) public inboundLimit` (L52-59); `setPeer(uint32,bytes32) public virtual onlyOwner` (L78); `setInboundLimit(uint32 srcEid, uint64 windowSeconds, uint64 capacity) onlyOwner` (L86; `InvalidRateLimit` if capacity≠0 and window==0); `inboundRemaining(uint32) view` (L97; `type(uint64).max` when unlimited); `setDelegate(address) onlyOwner` (L121); `allowInitializePath(Origin) view` (L126); `nextNonce(uint32,bytes32) pure returns 0` (L133 — "Zero selects the endpoint's default unordered delivery. Ordered delivery would let one stuck message block every later one for that route." L131-132); `oAppVersion() → (1,2)` (L137); `lzReceive(...)` (L142-154); internal `_lzSend` (L164; reverts `NoPeerConfigured`, `IncorrectFee` if `msg.value != fee.nativeFee`), `_quote` (L184), `_toBytes32`/`_toAddress`. Owner is `Ownable2Step`; constructor optionally calls `ENDPOINT.setDelegate(delegate_)` (L73).

Events: `PeerSet`, `InboundLimitSet`. Errors: `OnlyEndpoint`, `UntrustedPeer`, `NoPeerConfigured`, `IncorrectFee`, `InvalidRateLimit`, `InboundRateLimited(srcEid, used, capacity, windowEndsAt)`.

Invariants: every inbound message must satisfy *both* `msg.sender == ENDPOINT` and `peers[origin.srcEid] == origin.sender` with a non-zero peer (L149-151): "Cross-chain messaging has one dominant failure mode and it is always the same one: accepting a payload that did not come from the contract you think it did. Nomad, Wormhole and most of the rest reduce to a missing or forged origin check." (L18-20). "A zero peer is never trusted, so an unset route fails closed." (L29). Rate limit rationale: "Neither LayerZero's ONFT721 nor Hyperlane's HypERC721 has one, and that is the difference between a compromised DVN set costing one agent and costing all of them … A throttled message is not lost. LayerZero keeps an unexecuted payload retryable, so the cap converts a catastrophic drain into a delay — which is the entire point: it buys the time in which a human notices." (L44-51). Off by default "so that a deployment must opt in deliberately rather than inherit a number nobody chose" (L84-85). Honest scoping: "LayerZero's security ultimately rests on the DVN and executor configuration set at the endpoint, not here." (L32-33).

Tests: `Omni.test.ts` "rejects a message that did not come from the local endpoint" (`OnlyEndpoint`), "rejects a message from an unregistered peer on a configured chain" (`UntrustedPeer`), "refuses to send to a chain with no configured peer"; `Regressions.test.ts` L506-560 "refuses a zero-length window that would reset on every message", "caps inbound messages per window and lets the window refill".

**Reuse verdict: ADAPT** (keep both authentication halves and the rate limiter; decide whether the merged protocol tolerates an `Ownable2Step` owner over peers — IPSEITY's `ParleyPort` has "no admin/delegate ever, security config pinnable only at construction", which is the stricter stance).

### 2.4 `OmniAgentHome.sol` (6,979 B) — escrow on the accountable chain
API: `AGENTS`, `ANIMA` immutables (same address, L77-78); `mapping(uint256 agentId => uint32) public awayOn` (L54); `quoteSend(uint32 dstEid, bytes32 to, uint256 agentId, bytes options) view returns (MessagingFee)` (L85); `send(uint32 dstEid, bytes32 to, uint256 agentId, bytes options, MessagingFee fee, address refundAddress, bool acknowledgeAssetsRemain) payable nonReentrant returns (MessagingReceipt)` (L95-129); internal `_lzReceive` (L135-156), `_requireCleanReceiver` (L162), `_snapshot` (L166-180, reads `manifestOf`, `brainRoot`, `brainEpoch`, `modelOf().weightsRoot`, `sealPolicyOf`, `block.chainid`, `address(AGENTS)`).

Events: `AgentDeparted(agentId idx, dstEid idx, homeAccount idx, to, brainRoot, brainEpoch, strandedNativeBalance)`, `AgentReturned(agentId idx, srcEid idx, to)`. Errors: `AgentBusy`, `HomeAccountHoldsAssets(agentId, account, balance)`, `NotAgentOwner`, `AgentNotAway`, `WrongOriginChain(agentId, expected, actual)`, `InvalidReceiver`.

Design (quoted): "**Why escrow rather than burn-and-mint.** An agent's bond, reputation and validation history are chain-local claims other contracts hold against it. Burning the token on its home chain would strand all of that behind an id nobody owns, and an agent whose accountability can be left behind by bridging has no accountability at all." (L27-32). "**What does not travel, stated plainly.** The agent's ERC-6551 account is derived from its home chain id and home token contract, so the mirror on another chain has a *different* account … ERC-20 balances cannot be enumerated on-chain and therefore cannot be checked — the departure event publishes the account address precisely so a front-end can look … A check that claimed to be complete here would be a lie." (L34-41). "**A busy agent may not leave.** … the bridge equivalent of absconding." (L43-45). Receiver validation records a past bug: "A right-padded address is non-zero as a word but decodes to address(0) on arrival, and by then the token is already escrowed and the message reverts on every retry — the agent would be stranded in this contract permanently." (L104-107). Escrow before dispatch: "The token transfer also trips AnimaAgent's transfer hook, which pauses the agent and clears its autonomy policy — exactly right for a token about to be controlled from a different chain." (L121-123). Return auth: "Only an agent this contract actually sent out may come back, and only from the chain it was sent to. Without this, a compromised peer on any configured chain could mint itself a claim on an agent that never left." (L143-145).

Tests: "escrows the agent and carries a verifiable snapshot across", "refuses to bridge an agent that owes someone work" (`AgentBusy`), "refuses to strand assets in the home account without an explicit acknowledgement" (`HomeAccountHoldsAssets`, then succeeds with `true`), "refuses to bridge an agent the caller does not own", "rejects a return message for an agent that never left" (replayed delivery → `already delivered`), Regressions "rejects a right-padded receiver before the token is committed" (`InvalidReceiver`, token still owned by alice). `Lifecycle.test.ts` step 8 bridges and returns inside the whole-life story.

### 2.5 `OmniAgentMirror.sol` (9,528 B) — tradeable shadow, ERC-721
`struct Replica {bytes32 brainRoot; bytes32 manifestHash; bytes32 weightsRoot; uint64 brainEpoch; uint64 homeChainId; uint64 syncedAt; uint8 seal; uint32 homeEid; bytes32 homeToken; string agentURI;}` (L35-47); `uint32 public configuredHomeEid` (L51). API: `setPeer` override enforcing **one home route** (L74-80; `OnlyOneHomeRoute`): "Rejecting a second route at configuration time is recoverable; rejecting its packet after the source NFT was escrowed is not. Separate home collections need separate mirror deployments because ERC-721 numeric ids are collection-local." (L71-73); `isReplica() pure returns true` (L83: "Always true. Read it before treating this token as a bondable agent."); `replicaOf`, `tokenURI` (returns the snapshotted `agentURI`), `verifyManifest(agentId, bytes manifest) view` (L97: `keccak256(manifest) == committed`); `quoteSend`; `send(uint32 dstEid, bytes32 to, uint256 agentId, bytes options, MessagingFee fee, address refundAddress)` — **home-only**: "a mirror forwarded chain-to-chain would arrive from an endpoint the home side is not expecting; it would burn itself on departure and then revert on every delivery retry, stranding the escrowed original forever." (L150-154). `_lzReceive` tolerates re-mint under the same id (L127-132). Events `MirrorMinted`, `MirrorBurned`; errors `NotMirrorOwner`, `InvalidReceiver`, `UnknownMirror`, `OnlyHomeRoute`, `OnlyOneHomeRoute`.

Header: "**A mirror is not the agent, and this contract says so.** `isReplica()` returns true and there is no bond, no reputation, no validation history and no token bound account here … A protocol that let an agent's guarantees be duplicated by bridging would be issuing collateral out of thin air, once per chain." (L17-21). "The brain root is a snapshot taken at departure … This is honest staleness rather than a false claim of live state." (L28-30).

Tests: "rejects a second home route before it can strand a colliding source NFT", "burns the mirror and releases the original", "refuses to send a mirror the caller does not hold", Regressions "refuses to forward a mirror off its return route" (`OnlyHomeRoute`).

### Omni weaknesses
- No timeout/cancel/recovery for an accepted-but-undelivered packet (`TESTNET_AUDIT_2026-08-31` "Remaining production risks" 1-2; `TESTNET_AUDIT_2026-09-02` blocker 2).
- Scripts never configure an explicit DVN/executor stack (defaults).
- ERC-20 balances in the home account are not checked at departure (by admission).
- Mirror has a different ERC-6551 address and carries no bond/reputation — any "use all features from the NFT" story only works on the home chain.
- `Ownable2Step` owner over peers/limits/delegate.
- One home route per mirror collection.

**Reuse verdict: ADAPT / OPTIONAL.** For the merge goal (one NFT whose website, swap, social, launchpad and vault all live with it) a token bridge is not required; IPSEITY deliberately refuses to bridge tokens and partitions ids by chain. If multi-chain presence is wanted, this escrow+snapshot design (never burn) is the correct shape and the authentication/rate-limit base is reusable.

## 3. `sdk/src/index.ts` — reference hashing rules (772 lines)

Not a viem wrapper: "it is the reference implementation of the hashing rules" (L7-8). Peer dep `viem ^2.55`; ESM; not published to npm (sdk/README.md L7). Builds with `npm run sdk:build`.

Exports and what they mirror:
- Enums `SealPolicy {None, Committed, ReKeyed, SealedTEE, SealedZK, Threshold}`, `AgentStatus`, `ShardKind` (L26-51); interfaces `BrainShard`, `InferenceReceipt`, `PrivateEnvelopeContext` (L53-79).
- `AgentManifest` (L90-142): ERC-8004 `registration-v1` document + namespaced `anima` extension (`registry`, `agentId`, `mcp[]`, `pricing`, `model`, `gui: AgentGui {canonical https URL, contentUri (ipfs/ar/web3), entrypoint, version, modules?}`, `mesh`, `handles`, `markets`). JSON Schema at `schemas/anima-agent-manifest-v1.schema.json` (`additionalProperties: false`; test `ManifestSchema.test.mjs` proves the example validates and that an `executableCode` field is rejected).
- `agentWebUrl(origin, chainId, contract, agentId)` (L193-203): `https://<origin>/<chainId>/<contract lowercase>/<id>`; rejects non-https, credentials, query/fragment.
- `HandleKind` map + `handleKey(kind, value) = keccak256(abi.encode(uint8, string))` (L216-236) mirrors `AgentHandles.handleKey` (tested vs. contract).
- `serialiseManifest`/`manifestHash`/`canonicalise` (L250-408): RFC 8785 JCS; throws on NaN/Infinity and lone surrogates; drops `undefined`. "Publish the output of this function verbatim. A re-formatted copy — a pretty-printer, a proxy that re-serialises, a CMS that reorders keys — will fail `verifyManifest` against its own document." (L246-249).
- `verifyManifestBytes` (L263-296): hash first, parse second, bind `registrations[]` to the requested registry/agentId. `fetchVerifiedManifest` (L299-349): HTTPS only, no credentials, `redirect: "error"`, streamed 1 MiB cap, 10 s timeout.
- `shardLeaf`/`brainRoot` (L414-451): tags `keccak256("anima.BrainShard.v1")`, `keccak256("anima.BrainRoot.v1")`; ordered hash chain, not a Merkle tree: "reordering shards is a state change and produces a different root" (L438).

## 8. How is the web UI delivered, and how is NFT ownership verified? (explicit answer)

Three UI surfaces exist on `main`, and two more on unmerged branches.

**A. GitHub Pages "Sanctuary"** (`index.html`, `src/main.js`, `vite.config.js`, `.github/workflows/pages.yml`). A Vite-built static site at `https://venividis.github.io/Cutting-edge-technologically-advanced-NFT/`, loading Google Fonts and bundling viem. It is **off-chain**. It hardcodes `ANIMA = 0xb3d92c766e3cb356db381feb21958a9ebb974365` (src/main.js L120 — the `0xc591…` deployment, *not* the `0x0aeb…` one the README advertises) and `https://sepolia.base.org`. Ownership verification is **client-side**: `discover()` (L178) reads `totalMinted()`, calls `ownerOf(id)` for every id and keeps those equal to the connected address; it then renders a "Command Chamber" (status, seal, epoch, ERC-6551 account, daily horizon, fingerprint) and offers `setStatus`/`deployAccount` writes which are simulated (`simulateContract`) then sent through the injected EIP-1193 wallet. No signature challenge; no server; reads are open to anyone (`inspectAgent` by token id). The mint flow builds a **self-contained `data:application/json` metadata URI with an inline SVG** (L149-154) so wallets need no server/IPFS — a genuinely reusable idea. The landing page shows five fictional "beings" with fabricated bond/trust numbers (flagged as misleading by the Commons branch, which corrects them).

**B. `contracts/web/AnimaWeb3Renderer.sol` — ERC-4804 manual-mode on-chain page** (22,592 B runtime; 1,984 B under EIP-170). `resolveMode()` returns `"manual"` (L32-34) so a Web3URL client passes the whole path as fallback calldata; `fallback(bytes calldata path)` (L37-47) returns `abi.encode(string html)` for `/` (usage page), `/token/{id}/live` (full console) or a not-found page; token id parsed by `_tokenPath` (L49-64); HTML assembled by `string.concat` in a view call (`_token` L76-99) with the owner, ERC-6551 account and collection address interpolated server-side. Served through gateways such as `https://<renderer>.basesep.w3link.io/token/{id}/live` or natively as `web3://0x9160…75cd:84532/token/{id}/live` (`public/.well-known/anima.json` `rendering`). The page contains tabs OVERVIEW/IDENTITY/CONTROL/ADVANCED, a CONNECT WALLET button, lifecycle/guardian/operator/deployAccount actions and a "Simulate any ANIMA function" raw console. **Caveats that break the "no external dependency" goal:** the `<script type="module">` does `import … from "https://esm.sh/viem@2.55.19"` (L128) and hardcodes public RPCs for only 84532 and 11155111 (L129; other chains yield `rpc === undefined`). **Ownership gating:** none for reads — anyone with the URL sees the page; writes are only gated by the contracts themselves (`simulateContract` surfaces `NotAgentOwner`/`NotAgentController` reverts). The UI never compares `ownerOf(id)` to the connected address. Bug: seal labels `["NONE","SEALED TEE","ZK RE-ENCRYPTED"]` (L131) index a 6-value enum, so `Committed` (1) displays as "SEALED TEE". Test `Web3Renderer.test.ts` asserts the page contains the four panels, `createWalletClient`, `simulateContract`, the owner and account addresses, and `doesNotMatch(/github\.io/)`. Three renderer versions were deployed on Base Sepolia (history in the `0xc591…` record); the workflow commits the address to `main`.

**C. The token's own `tokenURI`** is whatever `agentURI` the controller set (`https://`, `ipfs://`, or a `data:` URI as the Sanctuary does). It is not generated by the renderer.

**D. Unmerged branch `fix/utility-workflows-20260904` (and its subset `upgrade/sanctuary-commons-3d-20260904`)** — the closest thing in this repo to "mint a website":
- `contracts/utility/FrozenClient.sol` (patch; runtime 848 B + 57 B per `ClientPart`): `ClientPart` stores up to 23,000 bytes of data as contract code prefixed with `0x00` (STOP) "the leading STOP makes calls inert"; `FrozenClient(address[] parts, bytes32 expectedHash)` validates ≤128 parts, prefix and sizes, reassembles with `extcodecopy`, and **refuses to deploy unless `keccak256(assembled) == expectedHash`**; views `partCount`, `readPart(i)`, `html()`. `scripts/utility-publish.mjs` splits `dist/ANIMA_Utility.html`, deploys parts + client, verifies whole-page `eth_call` reconstruction byte-for-byte, then pins `abi.encode(address client, bytes32 bundleHash)` under the NFT's metadata key `anima.client.v2` via `AnimaAgent.setMetadata`. `scripts/utility-recover.mjs` rebuilds the HTML from `eth_getCode` and the on-chain hash (optionally resolving the pin from the NFT) "and does not execute them". Measured (`docs/utility/evidence/summary.json`): bundle 609,226 bytes, 27 parts, publication gas **135,938,093** on a local chain; "Publication is intentionally restricted to chain 31337 and loopback". The pointer is owner-mutable ("immutable content is not an immutable pointer", `docs/utility/SECURITY.md`).
- The utility client (`src/utility/client.js`) gates owner actions with `ownerOnly(id)` = `ownerOf(id) == walletAddress` (L64) and verifies the whole deployment before enabling spending: `matchesRuntime` compares `eth_getCode` to the compiled release hash with solc immutable ranges zeroed (L7-11), checks diamond facet routing selector-by-selector against the loupe (L29-33), checks cross-contract wiring (`swap.ANIMA()`, `launch.AGENTS()`, `commons.WORK()`…, L36-38), and uses epoch-invalidated, re-simulated transaction plans with atomic approve→act→revoke batches via `AgentAccount.executeBatch` (L83, L123).
- `docs/commons/DEPLOYMENT.md` on `main`-adjacent branch is explicit that the Sanctuary website is "**not deployed on-chain by this release**" and that a production on-chain UI "requires an actual immutable chunk/manifest store, a hash-checked loader, a specified version policy".

**Bottom line for the merge:** ANIMA's only on-chain UI (B) generates HTML in a view function but depends on esm.sh and public RPCs and does not gate by holder; the only chain-anchored "website bundle" (D) exists on an unmerged branch, is local-chain-only, and is reachable through an owner-mutable metadata pin. Nothing here is a `tokenURI`-emitted, self-contained client like IPSEITY's. On-chain **wallet gating** exists in exactly one contract: `AnimaCommons.publish` requires `ANIMA.isController(agentId, msg.sender)` *and* an exact `getStateFingerprint(agentId)` match before a post may carry an agent badge; everything else is enforced by the underlying ANIMA/account/module contracts on writes, with reads public.

### 9.2 `contracts/utility/TimeLockVault.sol` (patch; 3,632 B; 13 tests)

I decompressed the payload into the scratchpad and confirmed the hashes match the workflow's pinned values (`bbe8f97b…`, `94d37714…`, `450dc48c…`, `87f1466c…`); the readable sources quoted above come from that patch. ## 12. Pitfalls recorded for the design team
1. `MockLZEndpoint` accepts `0x` options; the live message library rejects them — always `lzReceiveOptions()` (pinned bytes in `Sdk.test.ts`).
2. Public RPCs are load balancers: wait for code, take ids from receipt logs, block until the endpoint reaches the tx block (three real incidents).
3. `AgentCore`/`Lease` field order is normative (ERC-5646 fingerprint); append only.
4. Any token function must be in exactly one facet; `deriveFacetCut` throws otherwise — do not loosen.
5. No `try/catch` on gas-estimated paths.
6. NatSpec bare `@` breaks compilation.
7. Test counts in docs drift; measure before quoting.
8. Both published UIs point at **different** token addresses (`0xb3d9…` vs README's `0x0aeb…`), and both deployers' keys are gone/compromised.
9. Renderer: esm.sh dependency, 2-chain RPC map, seal-label bug, no holder gating, 1,984 B headroom.
10. AgentComms: no enumeration, owner-key pinning, ERC-20-only postage.
11. Omni: no packet-recovery state machine (Unichain #4 stuck); DVN defaults; ERC-20s not checked at departure; mirror has a different 6551 address.
12. Unichain Sepolia deployment uses a non-canonical ERC-6551 registry.
13. The utility branch ships source as an opaque patch applied by CI with push rights.
14. Commons: byte limits not character limits; invitation-only ≠ private; moderation ≠ deletion.
