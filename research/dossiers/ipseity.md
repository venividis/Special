## 1. Identity and thesis

IPSEITY is a fully on-chain ERC-721 of 4,096 tokens whose `tokenURI` returns, as a nested `data:` URI, a self-contained WebGL2 application — a 4-D polytope viewer plus a complete wallet client with its own keccak, ABI coder and EIP-712 — stored as contract bytecode in SSTORE2 shards. The same contracts serve an entire multi-page website over `web3://` (ERC-5219), run a per-token AMM whose curve is a function of the artwork's orientation, launch ownerless ERC-20s with Uniswap v4 hooks mined under `eth_call`, keep an indexer-free message archive in event logs, and give every token two ERC-6551 accounts: one that acts under a measured seal and one that structurally cannot spend. The repository's own sentence is the thesis: *"There is no server, no IPFS, no indexer, no external dependency anywhere — on chain or off. That absence is the product."*

Three disciplines shape everything in it. **EIP-170 is the design force**: the hub holds state and exposes `viewOf()`; behaviour lives in satellites that read the hub; when a contract nears 24,576 bytes a companion is added rather than the file grown (`DeskRooms`, `DeskWill`, `LaunchView`, `ConsoleRead.sels()`). **Comments are load-bearing**: box-header comments argue each design and record every bug in past tense, and the verifiers quote them. **Verification is written as attack**: 22 adversarial Node verifiers, a 13-claim adversary replay, a seven-agent simulation, a seeded shrinking fuzzer, and a Foundry-shaped suite executed without Foundry on `@ethereumjs/vm`, all under a 26-step `npm run check`.

Measured shape: 69 contracts with runtime bytecode, none over EIP-170, five within 6 % of it; 149 Solidity test functions across 8 suites (the README variously says 73, 135 and 158 — drift is a documented trap); `engine/ipseity.html` is 200,014 bytes of deployable source; `tools/` is ~20,000 lines of JS. Two live testnet deployments (Ethereum Sepolia 11155111, Base Sepolia 84532) each with 54 recorded contract addresses, a 2026-09-24 Sepolia exercise that touched every function family in 83 transactions, and one LayerZero V2 lane that carried a commons message between the two chains. The edition went **Ethereum-only** on 2026-09-18 (`fe990f7`); `CLAUDE.md` still describes five chain bands. Nothing is audited; Foundry has never run on this code; the curator is a single EOA on both testnets.

Relative to the GOAL, this repository is the closest of the four to the finished shape: it already has a swap (Pool), a messaging/social layer (Parley + Roster + sealed DMs + ENS names), a launchpad (Kiln + hooks + planner), and a vault (Reach + Grip + Locker + Succession + Consign) hanging off one ERC-721 — *and* two working mechanisms for the NFT to mint its own website with wallet-aware, holder-gated controls. What it lacks is a single unified app shell (two UI surfaces coexist), the filled console lanes that sit on an unmerged branch, three small unmerged security fixes, one unfixed re-entrancy in the Pool, and a wiring of the existing Timelock in front of the curator.

## 4. How the website is delivered, and how ownership is verified

### 4.1 Three delivery paths, all from chain

**Path A — `tokenURI` (the instrument).** `Ipseity.tokenURI(id)` builds a `TokenView` (owner, word, seed, both 6551 addresses and implementations, pool, counters, lock, kernel status) and hands it to `Renderer.facetURI(view, face)`. For face 0 the renderer concatenates `Engine.headBytes()` — a 300-byte plain prologue when packed — then `<script>self.$IPSE=[<quoted state script>,"<base64 gzip>"]</script>`, then the `INFLATE` loader, then nothing else, because in packed mode the body is the gzip of the whole document. The loader is an async IIFE that reads `self.$IPSE`, deletes it, inflates with `DecompressionStream("gzip")`, splices `<script>window.IPSE={…}</script>` before `</head>`, and `document.open()/write()/close()`. The `_state` object is the contract between chain and engine: `{id, collection, chainId, owner, account, grip, reachImpl, gripImpl, pool, seed, word, rot[6], w, form, hue, ops, strata, xfers, open, locked, block, depth, rpc}` (`Renderer.sol:99-116`). `_quote` escapes `"`, `\` and `<` → `\x3c` so no state string can end the outer script. The JSON, the SVG `image`, and the HTML `animation_url` are each base64'd; the result is ~103,808 bytes and costs 19.99M gas of `eth_call`. Faces 1 and 2 (`tokenURIAt(id, 1|2)`) are cheap SVG stills (3.32M / 13.72M gas) because *"a token that becomes invisible when a client is cautious is not really on chain."* The loader must declare nothing at global scope: `document.open()` keeps the Window, and a `const` in the loader once collided with the minified engine's top-level names and every packed token rendered black while 900 assertions passed (`verify.mjs` greps for this).

The instrument running inside a marketplace frame has an **opaque origin**: EIP-6963 wallets do not inject, `localStorage` throws (the engine uses that as its sandbox detector, `ipseity.html:2104`), and the page switches to read-only through a public RPC with `credentials:"omit"`. It can be looked at and not used.

**Path B — `Premises` (the site).** `Premises.request(string[] resource, KeyValue[] params)` (`Premises.sol:251`) is an ERC-5219 HTTP handler returning `(status, body, headers)`; `resolveMode()` returns the exact word `"5219"` (ERC-6860), without which a `web3://` client falls to auto mode and gets an empty call. Twenty page contracts are immutable constructor arguments passed as a struct ("seventeen flat addresses is past what even viaIR keeps on a stack"). The artwork routes — `/`, `/token/<id>/raw|live|face/<n>|sigil.svg` — are answered by Premises itself from the hub and renderer and never through a page: *"a compromised front door controls pages that link to and frame the artwork, and cannot alter one byte of the artwork itself, because it does not hold those bytes."* `/token/<id>/live` returns the identical `Renderer.document()` bytes as `text/html` on a real `web3://` origin for 4.48M gas — one fifth of `tokenURI`, with no double base64 — and is the route on which wallets inject and every instrument can sign. Every other route delegates: each page `view` function `string.concat`s `Chrome.head → nav → body → <script type="application/json" id="D">{…}</script> → Chrome.wallet → Desk.core → feature script → Chrome.foot(msg.sender, chainid)`. The config block carries every selector the client will send, each computed on chain by a local `_sel(sig) = bytes4(keccak256(sig))`, and every address, so the browser ships **no keccak, no ABI coder, and no floating point for amounts** (`Desk.CORE_JS`: `W/S/AD/pad/parse/fmt`, BigInt only; `TK` ticker whitelist; `Web.jsonEsc` so a `</script>` symbol cannot end the block). Responses carry `Cache-Control: public, max-age=15` (pages) or 86,400 (301s); one resource has one URL (trailing slash dropped, leading zeros refused) so a gateway's cache cannot be filled with aliases. A bad path is a 404 document that never echoes the path, not a revert. Reaching it: a native `web3://<premises>:<chainId>/…` client, the w3link.io public gateway, `tools/gateway.mjs` (every `GET` is one `eth_call`; `/__rpc` forwards twelve read methods only), or ENS: `Nameplate.text(node,"contentcontract")` answers `eth:0x<premises>` (ERC-6821 in ERC-3770 form; a CAIP `eip155:` form was found not to parse on a real gateway) so `web3://name.eth/chat` opens the chain-served site, and `<id>.parent.eth` resolves by ENSIP-10 wildcard.

**Path C — the console.** `/c/<id>[/<verb>]` → `PageConsole.doc(id, verb)` server-renders the crest (token, chain, holder, LED), the still, three identity sentences, seven verb buttons (`turn hold trade hand speak make look`) and the chosen lane from `ConsoleRead.look(id)`, which reads every satellite behind `extcodesize` **and** `try/catch` and returns a `reported` bitmask so "nobody answered" and "the answer was zero" are different facts. It seeds `window.CON={id, chain, hue, word, hub, owner, reach, grip, reported, sel{…}}`, inlines the stylesheet from one `ConsoleSkin` SSTORE2 store (raw, never gzipped — "a flash of unstyled console, on every load, forever") and the script from a second (`console.js + console-lanes.js`). Layering is stated and tested: no script → a correct page about the right token; script, no wallet → the walk and command line; script and wallet → controls. Every write goes through `propose(title, lines, tx)` which renders To/Value/Function, sends only on an explicit press, then `watch(h)` polls the receipt for three minutes. On HEAD the TRADE and SPEAK lanes are "unbuilt" notes; the unmerged branch fills them (§10).

### 4.2 How ownership is verified

**Reading is never gated, anywhere.** A page cannot know who is asking (`msg.sender` inside a page is the Premises address); the hub's `onlyOwner` comment and `Chrome.sol:224-228` both say the gate is a courtesy that hides a composer, not a fact.

**Client-side recognition** (what "connect your wallet and it verifies you hold the NFT" means here): `Chrome.WALLET_JS` collects every EIP-6963 announcer keyed by `rdns` (uuid regenerates per announcement), remembers the choice in `localStorage['ipse.wallet']`, and raises a picker when more than one wallet announces — *"otherwise one wallet could supply the terms and another could be asked to sign them."* `Desk.connect()` calls `eth_requestAccounts` and compares `eth_chainId` with the page's `D.chain`, throwing on mismatch before any read. The holding check is the collection itself: `balanceOf(wallet)` then `tokenOfOwnerByIndex(wallet, i)` for `i < min(n, 64)` (`DeskTalk.sol:160-165`, `DeskTerm.sol:180-185`), filling a "speaking as" list; `become(id)` sets `ME` and toggles `body.held`, and the CSS `.gate{…} body.held .gate{display:none}` swaps the connect card for the composer. Per-token pages `eth_call ownerOf(id)` and compare lowercase to the connected account (`PageSeal.MINE`, `DeskEstate.mine`, the console crest "you", the instrument's `needOwner()` which throws *"Only the holder can change this token. It is held by …"*). `/k/<id>/<key>` additionally refuses a wallet whose `eth_requestAccounts[0]` is not the key.

**Chain-side enforcement** is the only thing that holds: the authority predicates in the §2 diagram (hub `onlyOwner` = owner or Reach, `Ipseity.sol:291-299`, confirmed; Reach `onlySigner` = `ownerOf` exactly, resolved at call time so authority follows a sale; `mayActAs` = owner or Reach, never the renter; `Pool.onlyHolder` = `ownerOf`; strict owner in the estate contracts; `sessionAllows` on every `executeAsSession`). The confirm slab runs `eth_estimateGas` first, so a non-holder sees "would revert" before the wallet is asked. Delegation is on chain too (ERC-721 approval, ERC-4907 user or `leaseAgentOf`, bounded `grantSession` keys, epoch-scoped `authorizeUsage`), and the "prove you control this token" primitive for any third party is the Reach's ERC-1271 `isValidSignature` over an `Attestation(purpose, payload, nonce, deadline)` digest under the `IPSEITY_ATTESTATION` domain.

**There is no SIWE, no signed challenge, no server session, no token-gated byte.** The signed transaction is the proof, verified by the EVM. For the GOAL this is the shape to keep: it is the only verification that cannot be spoofed, and it needs nothing server-side.

## 5. Swap

**Pool (`src/Pool.sol`, 714 lines, 11,626 B).** One contract, one market per token id. `ownerOf(id)` is the sole liquidity provider and the only authority: *"selling the NFT sells the market — the reserves, the fee income and the price curve go with it in the same transaction, with no migration and no wrapper."* No LP shares (removes share accounting, first-depositor donation, every rounding question), no oracle, no TWAP, no flash loan. `struct Market {base, quote, rBase, rQuote (uint112), feeBps, open, bondUntil, curveWord, vBase, vQuote (uint128)}` is six slots. Lifecycle: `openMarket(id, base, quote, feeBps ≤ 500)` copies `sectionOf(id)` into `curveWord` and anchors; `deposit` pulls each side and credits **what arrived** (fee-on-transfer safe), caps only the side being added to (an earlier both-sides check locked a holder out under a bond), re-anchors unless bonded; `withdraw` is **never pausable** ("a pause that traps money is not a safety measure, it is a slower theft"); `swap(id, baseIn, amountIn, minOut, to, deadline)` pulls measured input, prices against the **stored** offsets, refuses output above half the real reserve (`MAX_OUT_BPS`), pushes output and measures it so `minOut` is checked against what the recipient actually received; `syncCurve` (holder, unbonded) copies the live word and re-anchors, with `pendingCurve` so a UI can offer the sync; `bond(id, until)` ratchets only, ≤ 365 days, survives transfer, freezes every exit and every term while additive operations stay open. `market(id)` returns twelve values for a front end in one call; `openIds(from, count)` enumerates open markets so directories need no indexer. The admin has five switches (`setPaused`, `bless`, `setAllowlistEnforced`, two-step handover) and the suite asserts against the compiled ABI that none takes a `uint`, "so none of them can name a thing to move."

**Curve (`src/lib/Curve.sol`).** `(x+vx)(y+vy)=k` where `v = r × concentration/BPS`, concentration ≤ 80,000 bps (8×) derived from the token's 4-D section: a closed-form cut direction `u = (−s₃, −s₄c₃, −s₅c₄c₃, c₅c₄c₃)` from the three w-plane angles, bucketed into a measured 8×16 `SLICE` table and an 8×4 `FALLOFF` table, measuring *deviation from rest*, so every solid at rest is 0 bps and the three non-w planes never move the price. `anchor` is called only on `openMarket/deposit/withdraw/syncCurve` — *"ANCHORING, not deriving … It used to be called on every quote, from the live reserves, and that was a critical bug … 400 units in came back as 718. The fuzz suite found it."* `amountOut` rounds the pool's remaining balance **up**; `spot` is display only.

**Venue + DeskTrade + PageSwap** are the secondary surface: a stateless Uniswap v3 reader (gas stipends on every staticcall, hand-decoded `observe` returns, `factory()` cross-check so a fake pool cannot be described as a Uniswap pool, `ROUTER_KIND` pinned beside the router because the two `exactInputSingle` shapes differ by one word and the wrong one does not revert) and a single-hop client that quotes every tier through QuoterV2 with a 30M-gas `eth_call`. The token list is **derived** from the pool's open markets (`lib/Assets.derive`), never fetched.

**Clients.** The flat site: `PageMarket` (swap card; `<select>` seeded from `openIds(0, 40)`; `/open` directory of 24 rows) and `PagePool` (holder's side; curve drift via `pendingCurve`, "a page that recomputes a contract's own derivation is a page that will one day disagree with it"), driven by `Desk.SWAP_JS/POOL_JS` with approve-then-swap as one button. The instrument: node MARKET (bit 10, sealed at birth — `BORN_OPEN = 0x987`, after the `0x587` bug shipped the money panel open and the picture sealed) reads `S.pool` from the state block, quotes with a 220 ms debounce, checks the quote against `maxOut` on the far side, and `propose()`s the swap with every calldata word decoded. The console TRADE lane (unmerged branch): the maker's whole bench plus a swap quoted at review time with the floor stated in words and a fifteen-minute deadline, exact-amount approval as the button's current step, never unlimited (invariants 152–153).

**Verified properties.** `Pool.t.sol` (28 tests, 6 fuzz): `testFuzz_invariantNeverFalls`, `testFuzz_roundTripNeverProfits`, `testFuzz_neverPaysMoreThanItHolds`, `test_renterCannotRepriceSomeoneElsesLiquidity`, `test_sellingTheTokenSellsTheMarket`, `test_bondSurvivesTheSaleAndBindsTheBuyer`, `test_pauseHaltsTradeButNeverCustody`, fee-on-transfer and silent-return tokens. `verify-pool.mjs` (62 assertions): a 200-trade walk asserting k against the anchored offsets read from `marketOf` words 8 and 9; `fuzz.mjs` 9 market properties; `agents.mjs` seven motives for 220 ticks; `verify-curve.mjs` 18 (contract cut direction matches the engine's `rot4` to 1e-6). Live: the 2026-09-24 Sepolia exercise ran `openMarket/deposit/swap/swap back/setFee/withdraw/syncCurve/setPaused/admin handover/bond` on markets `gld`/`slv`.

**Weaknesses (see §10 for the security debt).** ERC-20 pairs only; single LP per market (no aggregation); the holder can reshape an unbonded curve against a pending trade (bounded by `minOut`); a token with out-of-band balance moves can over-claim across two markets (monitored, not guarded; `bless` is the defence and testnets pass `enforce=false`); `Pool.onlyHolder` excludes the token's Reach while `Kiln`/`Parley` admit it (authority inconsistency across subsystems); and the unguarded `closeMarket`/`openMarket` re-entrancy path confirmed in source.

## 6. Messaging and social

**Parley (`src/Parley.sol`, 455 lines, 6,379 B).** Every message is a `Said(room indexed, from indexed, prev, prevFrom, seq, kind, body)` log; the contract keeps per room only `{last, count, opened, members, kind, open, steward, index}` and per token `lastSpoke`. `prev` is the block of the room's previous message, `prevFrom` the block of the token's previous message anywhere, so a client reads `stateOf(room).last`, asks `eth_getLogs` for exactly that block with `topics:[said, room]`, follows the *oldest* log's `prev`, and walks — *"Fifty messages is fifty single-block queries — the narrowest request `eth_getLogs` accepts — and no range scan at any point. The chain is the index. It costs one SSTORE to a warm slot per message."* (`last`/`count` share a slot.) Rooms: the commons (0; anyone speaks), groups (`found(by, name ≤ 48, open)`, key `keccak(1, index)`, steward may `invite`/`evict`, token itself must `join`), pairs (`whisper(from, to)` derives `keccak(2, min, max)` lazily; a raw pair key through `speak` is refused with `UseWhisper` because *"the derivation is where its membership is proved"*). `MAX_BODY` 1,024; kinds `PLAIN` and `SEALED` (nonce ‖ AES-GCM). The only unbounded array (`_seen[token]`, rooms ever entered) can be grown only by the token itself: *"an array a stranger can grow is an array a stranger can fill."* Eviction cannot unsay anything. `announce(token, x, y)` publishes a P-256 point **and the publishing owner**; every getter answers zero unless that owner still holds the token (`4fa41d0`, after the DM page was found promising privacy to a departed holder). `topics()` hashes the five event signatures on chain because *"a hash function shipped in a page is a hash function nobody checked."* `heads(rooms[])` is the 9-second polling primitive. Authority: `mayActAs(token, who) = who == ownerOf(token) || who == HUB.account(token)` (confirmed in source), never the ERC-4907 renter: *"a reputation is not a thing you can hand back at the end of the day."* No owner, admin or pause; the archive survives every site redeploy (`redeploy-site.mjs` reuses it: "a new Parley would not migrate the conversation, it would end it").

**Roster (`src/Roster.sol`, 3,267 B).** Stateless companion: `inWindow(room, from)` packs 256 memberships into one word from one `eth_call` (~550k gas of view, never mined); `invitedInWindow`, `membersOf`, `stewardedBy` derived from `groups()` counters; `kindOf` maps Parley's kind-0-for-unfounded to `NO_ROOM = 3` (a live Base Sepolia bug showed the commons as empty). Assumes contiguous ids from 1.

**ParleyPort (`src/ParleyPort.sol`, 4,246 B).** A LayerZero V2 OApp with no admin: peers, send/receive libraries and DVN config are written in the constructor, then `setDelegate(address(0))` — *"No admin, from the first block."* Only room 0 crosses ("groups stay local because a steward is an authority; pairs stay local because the two ids may live on different chains"); `echo(from, kind, body, options)` is a separate payable call so the local commons never depends on a bridge; `lzReceive(Origin, …)` refuses a body whose claimed eid differs from the DVN-attested `origin.srcEid`, drops the sender's block pointer and writes its own `prev = lastEcho` in the receiving chain's numbering, and emits `Echoed` under the port's own event — it cannot write into Parley at all. The file records the instructive bug: for one commit `lzReceive` was declared with `bytes calldata origin` (selector `0x42172c88`, "a dialect nothing on any chain speaks") and the mock endpoint had been written to match; `probe-port-abi.mjs` now proves dispatch at deployed bytecode by reaching a named refusal. Live: the same address `0x65d1e9d0…c7ae` on Base Sepolia and Ethereum Sepolia via a fresh nonce-0 key; one echo paid 104,037,152,596,558 wei, 323,518 gas, delivered in ~80 s into Base Sepolia block 45,828,666. Weaknesses: floats on default DVNs unless pinned (admissible for speech only, the file argues, never for custody); all-or-nothing across peers; the Sepolia port's immutable `PARLEY` points at a pre-redeploy archive; no client on HEAD renders `Echoed` (the unmerged console branch does).

**Nameplate (`src/Nameplate.sol`, 9,957 B).** An adminless ENS resolver: `addr(node)` → the Reach; `text("contentcontract")` → the Premises (ERC-6821 in ERC-3770 form); `text("avatar")` → `eip155:<chain>/erc721:<hub>/<id>`; `resolve(name, data)` → ENSIP-10 wildcard so `7.yourname.eth` means token 7 once a parent is claimed. **Custody is the stronger binding**: a NameWrapper NFT inside a token's Reach or Grip means that token with no transaction here; `heldBy` cross-checks registry owner == canonical `NAME_WRAPPER` → wrapper's `ownerOf(node)` is a contract → its `token()` names this hub on this chain → the account equals `hub.account(id)` or `hub.grip(id)` (`b43645e`, after a fake-wrapper spoof). `bind*` requires ENS ownership **and** holding the token; `*ByName` variants take DNS-wire names so the browser hashes nothing. Expiry is read from the registrar the registry names, keyed by label hash not namehash (a documented trap); renewal is permissionless. Vestigial after Ethereum-only: `Station`/`whereIs`, hardcoded gateway tables. Unmerged: the Sepolia NameWrapper address (`site.mjs:317` still carries mainnet's, confirmed).

**Clients.** `DeskTalk` (three refusals: no keccak, no `innerHTML` for chain strings, no range scans; four `textContent` elements per message; the held-token "speaking as" select), `PageTalk` (`/chat`, `/dm/<id>` with the seal bar), `PageRooms` (`/rooms` is "the only page on this site that cannot be rendered" server-side), `DeskRooms` (terminal words `invite evict roster`), `DeskSeal` (P-256 scalar = SHA-256 of `personal_sign("IPSEITY seal v1 · chain <c> · token <t>")`, imported as PKCS#8 so WebCrypto computes the point, static-static ECDH → AES-256-GCM; no forward secrecy, stated), `PageName`, `PageManifest._parley` (the archive's walk rule published as data). The console SPEAK lane on the unmerged branch walks the commons twelve hops and renders a second, visibly separate "HEARD FROM OTHER CHAINS" column from `Echoed` (invariant 156: foreign voices labelled, never mixed).

**Verified.** `Parley.t.sol` 26 tests (`test_theBoundAccountMaySpeakAndTheRenterMayNot`, `test_aPairRoomCannotBePostedToThroughSpeak`, `test_nobodyCanLengthenSomebodyElsesRoomList`, `test_transferInvalidatesTheFormerHoldersSealingKey`, `test_aGroupKeyIsNeverAPairKey`); `verify-parley.mjs` 37 (a deliberately second walker: 405 blocks of history in 3 single-block queries; two messages in one block do not loop, and the naive newest-log walk is run and watched loop; a `</script><img onerror>é🔥` body round-trips byte for byte); `verify-site.mjs` drives the shipped client ("every one of them asked for exactly one block"; sealed DMs end to end; a sale invalidates the key); `verify-port.mjs` 42; `verify-plate.mjs` ~62–73; `testnet.mjs` walks a real node's `eth_getLogs` and proves "a live node refuses a wallet speaking as a token it does not hold."

**Gaps for a social layer.** No reply/thread pointer beyond `prev`/`prevFrom`; no reactions or edits; groups are public, only pairs seal; no spam control beyond gas in a single commons; `MAX_BODY` with no multi-part convention; `HUB.account(token)` is a CREATE2 derivation call on every write.

## 7. Launchpad

**Kiln (`src/Kiln.sol`: `Coin` 1,492 B, `Kiln` 13,709 B, `Gate` 1,008 B).** `Coin` is "a token that cannot be used against the people who hold it": fixed supply, immutable decimals/totalSupply, no mint/burn-from/pause/blacklist/owner/upgrade/permit (invariant 97: "a launched coin has no owner because its ABI has none"). `Kiln.launch(token, name, symbol, decimals, supply, salt)` requires `mayActAs(token, msg.sender)` (owner or Reach, never a renter; `ownerOf` wrapped in `try/catch`), deploys by CREATE2 with `salt' = keccak(msg.sender, salt)` so a mempool watcher cannot take the address, mints the supply to the launcher, records `launcher/launchedBy/launchedAt`, and exposes `recent(from, count)` and `coinAt(...)` prediction. The thesis of the file: *"the client this collection ships has no keccak-256, on purpose. This contract does. `mine` is a view function that walks salts … the expensive, keccak-shaped part of deploying a hook is a read, and reads are free."* `mine(initCodeHash, flags, from, tries)` lays out `0xff ‖ deployer ‖ salt ‖ initCodeHash` once in assembly and moves only the salt word, requiring an **exact** match of the low 14 bits (a spare bit set means the PoolManager hands the hook a callback it does not implement); bounded because `eth_call` has a ceiling (the client asks 60,000 per window, up to 12 windows; expected ~2¹⁴ tries). `deployHook(kind, salt, arg)` CREATE2s the recipe and then **checks `Hook.flags(hook) == wanted` or reverts `WrongFlags`** — *"A lock that is never consulted looks exactly like a lock."* `band()`/`facetArg()`/`recipeHash()` let the page preview and pack a Facet recipe with "the contract that unpacks it is the one that packs it." The v4 `PoolKey/SwapParams/ModifyLiquidityParams` structs are duplicated locally in `Kiln.sol` and `Facet.sol` because callbacks are matched by selector and v4's `Currency`/`IHooks` are user-defined value types that ABI-encode as `address`.

**Gate** is "the one hook a launchpad actually needs": `beforeSwap` reverts `NotOpenYet` before `OPENS`; `beforeRemoveLiquidity` reverts `StillLocked` before `UNLOCKS`; both immutable. *"These are exactly the bits a trap has … What makes this hook safe is not the shape. It is that both timestamps are immutable."* **Facet** returns `FLOOR + (CEILING − FLOOR) × concentration(section)/80000 | OVERRIDE_FEE` from `beforeSwap`, refuses non-dynamic-fee pools in `beforeInitialize` ("the hook deploys, the pool works, every swap charges the key's static fee, and the returned override is discarded in silence"), and snapshots the section only on owner-called `syncFee` (`375917e`: before that a renter controlled the LP fee by turning the artwork). Why a fee and not a custom curve: *"The worst a bug here can do is charge the wrong fee inside a band that was fixed at deployment."* **GateFacet** (unmerged branch `hciyvv`) combines both in one immutable hook and locks only negative liquidity deltas so PositionManager's zero-delta fee collection works during the lock. **`lib/Hook.sol`** reads the fourteen permission bits off any address and names them in plain English with the dangerous ones in caps ("CAN REFUSE LIQUIDITY BEING TAKEN OUT"); `PageHook` renders that for any address with JavaScript off.

**V4PositionPlanner (5,928 B).** A view that returns canonical `modifyLiquidities(bytes, uint256)` calldata (`[MINT_POSITION, SETTLE_PAIR]`, `[INCREASE, SETTLE]`, `[DECREASE, TAKE]`, `[BURN, TAKE]`) and the native `value`, computing liquidity from `Tick.sqrtAt`/`Mul.mulDiv`; the wallet forwards the bytes unchanged. HEAD's `mintPlan` requires `KILN.launcher(coin) == msg.sender && mayActAs` (confirmed at `V4PositionPlanner.sol:81`), which strands authority after the NFT is sold; the branch relaxes it to `mayActAs` only ("Authority follows the NFT"), reads each position's `PoolKey` from `getPoolAndPositionInfo(positionId)` instead of the form, and prices mints from StateView's `getSlot0` with the block reported.

**DeskLaunch + PageLaunch + LaunchView.** Four steps: (1) `coinAt` preview → `launch` with two hand-encoded `string`s whitelisted to printable ASCII "so one character is one byte"; (2) choose Gate (`(opens<<64)|unlocks`) or Facet (`facetArg` through the Kiln), `recipeHash`, `mine` under `eth_call` at 30M gas, `deployHook`; (3) v4 `initialize((address,address,uint24,int24,address),uint160)` — "six flat words with no offset … the one v4 entry point a client with no ABI coder can build on its own" — with the two-way dynamic-fee guard (a dynamic-fee pool behind a plain Gate charges nothing forever and cannot be repaired); (4) `mintPlan` → `approve(Permit2)` + `Permit2.approve(token, PositionManager, amount, deadline)` → `send(positionManager, data, value)`. `PageLaunch` is at 95.6 %; `LaunchView` exists only to hold step-4 markup. **Locker** is the launchpad's "team tokens locked" primitive (§8). Deliberately absent: a bonding-curve or ETH raise phase; a recorded pool key per coin (a page cannot find a coin's pool without the user re-entering it); OFT bridging of launched coins (refused in `OMNICHAIN.md`).

**Verified.** `verify-launch.mjs` (49+ assertions) through `MockPoolManager`, which dispatches by the real selectors and consults a hook only for the bits its address carries (hooks are placed at addresses with the mask cleared then flags set): Gate shut/open/locked/released; Facet rest = floor, owner sync raises ≤ ceiling, renter cannot; static-fee pool refused at init; flagless address never consulted; one mined salt → same address on every chain, recomputed by hand; band packing round-trips; served-text regexes for the dynamic-fee guards. `verify-site.mjs` drives `/launch` with a DOM shim: launch lands where `coinAt` said; mined gate at `0x…280` bits; `initialize` reaches the manager with sorted currencies. `V4PositionPlanner.t.sol` 6 tests (12 on the branch). Live: Kiln deployed on both testnets, but **no `launch`/`deployHook` transaction appears in any live record**, and Facet/Gate have only ever executed against the mock ("is not v4").

## 8. Vault and accounts

**The Reach (`src/IpseityAccount.sol`, 1,119 lines, 13,461 B).** The reference ERC-6551 account plus one addition, a seal, argued from the reference implementation's structural gap: *"the holder can empty the account at any moment, including between agreeing a price for the token and settling it."* The seal is enforced by **measurement, not a selector blocklist** — *"A firewall that enumerates is a firewall with a hole in it shaped like whatever it has not heard of"* — : before a sealed call the account snapshots its ether and `balanceOf(this)` on every manifest asset (≤ 16) and `ownerOf` on every guarded NFT piece (≤ 8); after the call nothing may be smaller (`Shrank`), readable assets may not have gone blind (`WentBlind`), pieces must still be held (`PieceLeft`). The one thing measurement cannot see, a standing approval, is handled by deny-by-default: while sealed, a call to a manifest asset (or a guarded piece's collection) may carry only `transfer`/`transferFrom`; every other word — including `balanceOf`, `claim`, and every approval/permit shape — reverts `NotSafeWhileSealed(sel)`. (A six-selector blocklist was walked straight through with Permit2's `approve(address,address,uint160,uint48)`: "Same standing custody, different word, not on the list. It never would be.") `seal(until)` ratchets only, ≤ 365 days. *"A sealed vault can still vote, claim, compound, sign, and call anything that leaves it no poorer … a vault that cannot act is not a vault, it is a safe."* `execute` is CALL only (`OnlyCall`; no delegatecall ever); `executeBatch` (≤ 16) snapshots once around the whole batch so "withdraw from one venue, deposit into another" is allowed. ERC-1271 under seal is domain-separated: the account signs only `IPSEITY_ATTESTATION` typed data with nonce and deadline (`retireAttestations` bumps every signature the account ever gave) and is *"structurally incapable"* of signing any venue's order hash. `onlySigner` = `ownerOf(tokenId)` exactly — operators, approvees and renters cannot act through the Reach. The address derives from the implementation, so "this code is the code forever."

**Session keys** are the agent surface: `grantSession(key, expires ≤ 365 d, spendCap, targets[≤16], selectors[≤16])`; `executeAsSession(to, value, data)` checks an active, unexpired session whose `mark == hub.statsOf(id).xfers` (the hub's transfer counter, so a sold-and-bought-back token does not revive retired keys), target and selector on **epoch-keyed** allowlists (`revokeSession` used to `delete` the struct and leave the mappings standing: "Grant [poolA], revoke, re-grant [poolB], and it can still reach poolA"), cumulative native spend, no call to the account itself (`NoPrivilegeEscalation`), and for approval-shaped calls the **actual spender argument** (Permit2's second address) must be on the target list. The cross-product of targets × selectors is documented, not fixed: "one key per pair. Keys are free; storage is not." `AGENT.md` sketches the MCP wiring: `propose` and `act` are separate tools, and `sessionAllows(key, to, selector)` is checked as a view before sending.

**The Grip (`src/GripVault.sol`, 162 lines, 1,933 B).** *"It receives and it does not spend. There is no `execute`, no `withdraw`, no sweep, no rescue, no owner override, and no admin. Read the ABI."* Everything the Reach costs "exists because the capability to spend exists and is being policed. This contract does not police the capability. It does not have it." Its only non-view functions are the three `onERC…Received`; `isOneWay()` is true in the ABI; `supportsInterface` declines `IERC6551Executable` so a client that checks before calling `execute` is told the truth; signers and signatures are always refused. A mistaken transfer in is permanent, and the vault page says so before building the calldata. `verify-vault.mjs` asserts all of this against the compiled ABI.

**The three seals the site exposes at `/seal`:** the **bolt** (`lock/unlock`, ERC-5192/6454, `onlyOwner` = owner or Reach — an approvee could once `unlock` and take the token: "an approval is precisely what a phished wallet has already given away"); the **account seal** above; and the **sealed kernel** (`sealKernel(id, hashes[], to)`, `transferWithKernel` re-sealing under an `IDataVerifier` set once and never swapped, `cloneWithKernel` payable at mint price after "an adversarial review pulled eight free tokens out of a single mint", `kernelStatus` derived as `ownerOf == sealedOwner` with no setter, `authorizeUsage` grants scoped to an owner epoch). No verifier exists in any deployment; `kernelProved` is universally false; the stance on ERC-7857 is an explicit refusal (`Standards.sol:159-173`).

**Estate.** **Lease**: terms stamped with their author so a seller's terms cannot re-arm for a buyer; `rent` with exact `msg.value` and `maxPerDay`; rent escrowed and vested; breakage *observed* from `rawUserOf`/`userExpires` (not asserted) and "elapsed" measured to the last block the lease was seen intact; `earned[token]` so the buyer collects what the seller's tenancy accrued; `leaseAgentOf` is a per-token power narrower than approval ("Handing a rental contract the right to sell the token in order to let it lend the token is a capability an order of magnitude wider than the thing it authorises"); no fee, no renewals, no order book. **Locker**: `lock(token, amount, until ≤ 3650 d)` records the balance difference, `claim` after `until`, `extend` only longer, `give(id, to)` — "most usefully into a token's own 6551 account, so a locked treasury travels with the NFT when the NFT is sold"; `lockWithPermit` swallows permit failure on purpose (front-runnable); `nonReentrant` after an ERC-777-style callback nested a lock. **Consign**: title moves to the escrow, use stays with the seller as ERC-4907 user; `buy(agreed)` must equal the current `ask` (`PriceMoved`); royalty honoured first; pull-payment `owed`; `reclaim` after term by anyone; deliberately no `onERC721Received`. **Succession**: `arrange(id, to | toToken, quiet 30–3650 d, notice 7–365 d)`; `summon` by anyone starts the second clock; `claim` moves the token via a standing ERC-721 approval; only `arrange`/`stillHere` count as life, after a stranger reset the silence with `embody` ("Measured before it was fixed"); `wouldPass` returns ten status codes "because 'this will not work' is useless to somebody who arranged their estate." **Timelock** (`lib/Timelock.sol`): 7-day delay, 14-day grace, admin rotation only through its own queue — verified, deployed nowhere in front of anything.

**Pages**: `/token/<id>/vault` (both hands with `code.length` deployed check; `give` into the Grip with the permanence warning; `verify` shows the Reach's EIP-712 domain), `/seal`, `/keys` (chips carry on-chain-hashed selectors; `grantSession` laid out by hand with the address/bytes4 alignment trap recorded; `sessionCurrent` shown as "retired when it sold"), `/k/<id>/<key>` (the key's own door: refuses a wallet that is not the key; asks `sessionAllows` before building `executeAsSession`), `/lock`, `/estate`, `/token/<id>/rent`.

**Verified.** `verify-vault.mjs` (97 runtime / 116 static assertions): a drainer "with a function name no list has"; Permit2 shape; ether; delegatecall; ERC-1271 refused while sealed; seal survives sale and binds the buyer; Grip ABI shape; session bounds; blind asset named and releasable mid-seal while visible ones are not; batch atomicity; `SealBreaker` manifest renumbering re-entrancy; guarded NFT moved-then-dropped; session dies on sale and buy-back. `verify-findings.mjs` replays eight vault claims. `verify-estate.mjs` 67; `verify-timelock.mjs` 24; `Lease.t.sol` 26 (two fuzz: the split never loses or creates ether; the holder never vests more than time delivered). Live on Sepolia: `execute/executeBatch/grantSession/session spend/revoke/retire/guard/unguard/guardNFT/seal` all exercised.

**Weaknesses.** Hard dependency on the reference 6551 proxy footer offset `0x4d` and on `statsOf`'s 4-word shape; ERC-1155 cannot be guarded by identity; `spendCap` counts native value only; a sealed Reach cannot `claim()`/`vote()` on a promised asset; Consign freezes the Reach for the term (owner is Consign) and `transferFrom` retires its session keys; Succession needs a standing approval a marketplace `setApprovalForAll` would not safely provide; the storage layout is frozen at deployment; unaudited (MAINNET_READINESS names the Reach and Lease as audit gates).

## 9. The 20 most valuable unique ideas to carry forward

1. **State injected into a gap between head and body shards.** `tokenURI` writes `window.IPSE={…}` between `Engine.headBytes()` and `bodyBytes()`; the engine reads it and never searches a string for a marker (`Engine.sol:6-28`, `Renderer.sol:99-116`).
2. **gzip shards inflated by `DecompressionStream`, with a loader that declares no global and passes the payload on a property** (`Renderer.sol:50-60` `INFLATE`; `verify.mjs:174-189`). The packed document loads for 8.86M gas vs 23.58M raw.
3. **The same bytes served twice: `tokenURI` for marketplaces, `/token/<id>/live` on a real origin for wallets** — 19.99M vs 4.48M gas, and the only way EIP-6963 injection works (`Premises.sol:504-528`; invariant 9d asserts byte equality).
4. **ERC-5219 router with artwork never through a page, `resolveMode()`, one URL per resource, 404-not-revert, zero state** (`Premises.sol`; `verify-premises.mjs`).
5. **Selectors and topics computed on chain and emitted in a JSON config block; the browser ships no keccak, no ABI coder, no float** (`Desk.sol:24-45` `_sel`, `Parley.topics()`, `verify-site.mjs:627-691`).
6. **Two ERC-6551 accounts at two salts: an acting Reach and a receive-only Grip whose guarantee is that the spend function was never written, asserted against the compiled ABI** (`Ipseity.sol:147-168`, `GripVault.sol`, `verify-vault.mjs:284-300`).
7. **A seal enforced by measurement (balances before/after every manifest asset, ether, every guarded piece) plus deny-by-default on promised targets, with batch-wide snapshots** (`IpseityAccount.sol:740-832`).
8. **Session keys bounded four ways and stamped with the hub's transfer counter so they die on sale and do not revive on buy-back; epoch-keyed allowlists for O(1) revoke; the actual spender argument checked for approval shapes** (`IpseityAccount.sol:434-685`).
9. **Domain-separated ERC-1271: a sealed account can attest who it is but is arithmetically incapable of signing any venue's order** (`IpseityAccount.sol:979-1110`) — the login primitive for any third party.
10. **One AMM per token id with `ownerOf` as the sole LP; selling the NFT sells the exchange with no migration** (`Pool.sol:22-33`).
11. **Anchored virtual reserves written only on liquidity/curve change, never by a trade, with a `CurveAnchored` event and the fuzz property that caught the 400→718 leak** (`Curve.sol:240-258`, `fuzz.mjs:328-384`).
12. **The ratcheting bond that survives sale and freezes every exit and every term; admin switches that provably cannot name an asset; withdrawal that can never be paused** (`Pool.sol:76-105`, `verify-pool.mjs:461-475`).
13. **The chain is the index: back-linked event logs (`prev`/`prevFrom`) read with single-block `eth_getLogs`; derived pair rooms; permission recorded, entry self-performed; owner-bound sealing keys** (`Parley.sol:28-39, 106-111, 340-383`).
14. **Hook-salt mining as a `view` so a keccak-less client deploys Uniswap v4 hooks under `eth_call`; post-deploy `WrongFlags` check; sender-mixed CREATE2 salts; `/hook/<address>` reading powers off the address bits** (`Kiln.sol:41-58, 250-296`, `lib/Hook.sol`).
15. **A non-custodial Solidity "planner" that returns canonical PositionManager calldata so the browser never needs a recursive ABI coder** (`V4PositionPlanner.sol`; take the branch version).
16. **Custody is the ENS binding: a name NFT inside the token's 6551 account *is* the record, cross-checked three ways; ERC-6821 `contentcontract` so `web3://name.eth/` opens the chain-served site; ENSIP-10 numeric wildcards so every token has a name at mint** (`Nameplate.sol:38-92, 381-420, 562-612`).
17. **"Zero" and "no answer" are different facts: `extcodesize` + `try/catch` on every satellite read, a `reported` bitmask, "not reported" strings in the UI** (`ConsoleRead.sol:26-68`; the cause: Solidity's own `extcodesize` check reverts before `catch` can see it).

## 10. Weaknesses, incompatibilities with the GOAL, and security debt

### 10.1 Incompatibilities and structural problems

- **Art-specific state is wired into the money.** `Pool.curveWord`, `Curve.concentration`, `Facet.fee` and `Kiln.band` all consume the 4-D section word. The unified token will not have one; the concentration source must become pluggable (`concentration(bytes32) → bps ≤ 80_000` fed from whatever per-token signal the merge chooses, or a holder-set number).
- **Two UI surfaces coexist.** The flat site (19 routes, `Chrome`'s serif/gold at 94.8 % of EIP-170) and the console (`/c`, mono/hue) are both live; the spec's redirects and Chrome retirement did not ship; `/door` sends newcomers to `/c` and `navTop` sends them back. The GOAL needs one shell.
- **The console lanes are thin on HEAD.** TRADE and SPEAK are "unbuilt" notes, HAND is transfer only, MAKE is mint only. The fill (692 lines of `console-lanes.js`, `ConsoleRead.sels()` with 29 selectors, `PageConsole(…, parley, port)`, 96 Chromium assertions) is on `claude/claude-md-docs-8vvyc8`, six commits ahead and 53 behind.
- **The WebGL field is ~60 % of the engine's bytes and the whole 20M-gas read budget**, and `tokenURI()` cannot be served by any node that applies EIP-7825's 16,777,216-gas transaction cap to `eth_call` (hardhat's Osaka node did; the repo pins Cancun to dodge it). Marketplaces call `tokenURI`, not `/live`. The GOAL's app should be the lighter console-style document and `/live` the primary route.
- **Marketplace frames cannot sign** (opaque origin) — by design and unavoidable; the instrument's "connect" verb leaves for the console on the site origin.
- **Ethereum-only since `fe990f7`**, with drift: `CLAUDE.md`, `CONSOLE.md` §E.5 and `verify-portal.mjs` still describe five chains; `site.mjs` `bandOrWhole` now throws on Base Sepolia so `testnet.mjs` cannot reproduce the Base Sepolia record (W1); the ANIMA repo lives on Base Sepolia.
- **Authority predicates disagree across subsystems**: `Pool.onlyHolder` is `ownerOf` exactly; `Kiln`/`Parley`/`Consign`/`Succession` admit the Reach; the hub's `onlyHolder` admits approvees. A session key on the Reach can launch a coin and speak but cannot deposit into the token's own market. The merge must pick one ladder.
- **Pool is ERC-20-only** (no native ETH pairs), single LP, no aggregation.
- **Pages are within 2–6 % of EIP-170** (DeskTerm 97.3 %, PageLaunch 95.6 %, Desk 95.2 %, Chrome 94.8 %, PageManifest 94.0 %); every added feature needs a companion contract.
- **Wallet discovery is inconsistent**: Chrome/Desk use the EIP-6963 chooser; `console.js`, `console-lanes.js` and `PageKey.KEY_JS` use `window.ethereum` only, so "the signing wallet is chosen, never raced" does not hold on the console or the agent door.
- **Unlimited approvals** on the flat swap/pool cards (`(1n<<256n)-1n`); the branch console moved to exact amounts.
- **No kernel verifier exists** anywhere; the sealed kernel is a stance, not a feature; sealing does not make a seller forget the payload.
- **Succession needs a standing ERC-721 approval** to the contract; **Consign** freezes the Reach for the term.
- **Documentation drift**: test counts 73/135/158 vs 149 measured; `verify-site` 395 vs 586; README bytecode table stale by 600–1,100 B; `DEPLOYMENTS.md` "Live now" lags both JSONs; `test/Standards.t.sol` referenced but absent; `Seal.s.sol` referenced but absent; `AGENT.md` says `services/1`.
- **Dead code**: `IIpseity.userOf` in Pool, `Kiln.AlreadyLaunched`, hub `IsLocked`, `DeskUni._selCivic/_selPos`, Chrome's `.tess4` CSS, `DeskTrade`'s prose-only limit-order client, `DeskEstate`'s `ip:account` listener nobody dispatches.
